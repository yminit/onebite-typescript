# Section 1 - 4. 타입스크립트 컴파일러 옵션 설정하기

**1. 컴파일러 옵션이란?**

TypeScript 컴파일러의 동작 방식을 프로젝트에 맞게 설정하는 기능이다.

```text
TypeScript 코드
→ 타입 검사
→ JavaScript 변환
```

컴파일러 옵션으로 다음 내용을 설정할 수 있다.

```text
JavaScript 변환 버전
모듈 시스템
소스 코드 위치
컴파일 결과 위치
타입 검사 수준
컴파일 대상 파일
```

---

**2. tsconfig.json**

컴파일러 설정은 프로젝트 최상위의 `tsconfig.json`에 작성한다.

```text
section1
├─ src
├─ package.json
└─ tsconfig.json
```

생성:

```bash
tsc --init
```

---

**3. 이번 학습에서 사용할 설정**

```json
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "commonjs",
    "skipLibCheck": true,
    "rootDir": "./src",
    "outDir": "./dist",
    "strict": false,
    "moduleDetection": "force"
  },
  "include": ["src"]
}
```

---

**4. target**

```json
"target": "ESNext"
```

TypeScript를 **어떤 JavaScript 버전으로 변환할지** 결정한다.

```text
TypeScript
→ target에 맞는 JavaScript
```

`ESNext`는 최신 JavaScript 문법을 대상으로 한다.

---

**5. module**

```json
"module": "commonjs"
```

컴파일된 JavaScript에서 사용할 **모듈 시스템**을 지정한다.

이번 학습에서는 CommonJS를 사용한다.

```text
TypeScript
import / export
↓
컴파일
↓
CommonJS 방식
```

CommonJS에서는 대표적으로 `require`, `exports` 방식이 사용된다.

---

**6. skipLibCheck**

```json
"skipLibCheck": true
```

외부 라이브러리의 타입 선언 파일인 `.d.ts` 검사를 생략한다.

```text
외부 라이브러리 타입 선언
→ 검사 생략

직접 작성한 TypeScript 코드
→ 계속 타입 검사
```

라이브러리 타입 검사로 인한 불필요한 오류나 컴파일 부담을 줄일 수 있다.

---

**7. rootDir과 outDir**

소스 코드 위치:

```json
"rootDir": "./src"
```

컴파일 결과 위치:

```json
"outDir": "./dist"
```

```text
src/index.ts
↓ tsc
dist/index.js
```

폴더 구조도 그대로 유지된다.

```text
src/common/util.ts
↓
dist/common/util.js
```

즉,

```text
rootDir
→ 원본 코드 위치

outDir
→ 컴파일 결과 위치
```

이다.

---

**8. strict**

```json
"strict": false
```

TypeScript의 엄격한 타입 검사 기능을 사용할지 결정한다.

이번 학습에서는 `false`로 설정한다.

```text
strict: false
→ 일부 엄격한 타입 검사 비활성화
```

예를 들어 일부 상황에서는 매개변수 타입을 명시하지 않아도 오류가 발생하지 않을 수 있다.

```ts
const hello = (message) => {
  console.log(message);
};
```

현재 단계에서는 강의 설정에 맞춰 `false`를 사용한다.

---

**9. moduleDetection**

```json
"moduleDetection": "force"
```

모든 TypeScript 파일을 독립된 모듈로 처리한다.

설정하지 않으면 `import`나 `export`가 없는 파일들이 전역 공간을 공유할 수 있다.

```ts
// chapter1.ts
const num = 1;
```

```ts
// chapter2.ts
const num = 2;
```

`force`를 사용하면 각 파일을 별도 모듈로 처리하므로 같은 이름을 사용해도 충돌을 줄일 수 있다.

---

**10. include**

```json
"include": ["src"]
```

컴파일할 파일의 범위를 지정한다.

```text
src
├─ index.ts
├─ hello.ts
└─ test.ts
```

이후 파일을 하나씩 지정하지 않고 다음 명령만 실행하면 된다.

```bash
tsc
```

`src` 내부의 컴파일 대상 파일들이 함께 처리된다.

---

**11. 컴파일과 실행**

TypeScript 전체 컴파일:

```bash
tsc
```

결과:

```text
src
↓
tsc
↓
dist
```

컴파일된 JavaScript 실행:

```bash
node dist/index.js
```

전체 흐름은 다음과 같다.

```text
src에 TypeScript 작성
→ tsc
→ 타입 검사 및 컴파일
→ dist에 JavaScript 생성
→ node로 실행
```

---

**12. 옵션별 핵심 역할**

```text
target
→ JavaScript 변환 버전

module
→ 모듈 시스템

skipLibCheck
→ 외부 .d.ts 검사 생략

rootDir
→ 원본 코드 위치

outDir
→ 컴파일 결과 위치

strict
→ 타입 검사 엄격도

moduleDetection
→ 파일을 모듈로 처리하는 방식

include
→ 컴파일 대상 범위
```

---

**13. 핵심 정리**

* TypeScript 컴파일러 설정은 `tsconfig.json`에 작성한다.
* `tsc --init`으로 기본 설정 파일을 만들 수 있다.
* `target`은 JavaScript 변환 버전을 결정한다.
* `module`은 사용할 모듈 시스템을 결정한다.
* `rootDir`은 TypeScript 소스 위치이다.
* `outDir`은 JavaScript 출력 위치이다.
* `skipLibCheck`는 외부 타입 선언 파일 검사를 생략한다.
* `strict`는 타입 검사 수준을 결정한다.
* `moduleDetection: "force"`는 각 파일을 독립된 모듈로 처리한다.
* `include`는 컴파일할 파일 범위를 지정한다.
* 현재 핵심 흐름은 **`src의 TypeScript → tsc → dist의 JavaScript`**이다.
