# Section 1 - 1. JS의 단점과 TS의 장점

**1. 타입 시스템이란?**

타입 시스템은 **값과 변수의 타입을 어떻게 결정하고 검사할지 정한 규칙**이다.

```text
타입을 언제 결정할까?
타입을 어떻게 검사할까?
어떤 값을 같은 타입으로 볼까?
```

대표적으로 **동적 타입 시스템**과 **정적 타입 시스템**이 있다.

---

**2. JavaScript는 동적 타입 시스템**

JavaScript는 변수의 타입을 실행 중에 결정한다.

```javascript
let value = "hello";

value = 10;
```

하나의 변수에 서로 다른 타입의 값을 넣을 수 있어 유연하다.

하지만 타입 오류를 실행 전에 발견하기 어렵다는 단점이 있다.

```text
잘못된 타입 사용
→ 실행
→ 런타임에서 오류 발생 가능
```

규모가 큰 애플리케이션에서는 이런 런타임 오류가 안정성 문제로 이어질 수 있다.

---

**3. 정적 타입 시스템**

C, Java 같은 언어는 코드를 실행하기 전에 타입을 검사한다.

```text
코드 작성
→ 타입 검사
→ 문제가 없으면 실행
```

장점은 타입 관련 실수를 실행 전에 발견할 수 있다는 것이다.

반면 모든 타입을 직접 명시해야 하는 경우 코드 작성이 번거로워질 수 있다.

---

**4. TypeScript의 방식**

TypeScript는 JavaScript의 유연함을 유지하면서 **실행 전에 타입을 검사**한다.

```text
JavaScript
→ 실행 중 타입 결정

TypeScript
→ 실행 전에 타입 검사
```

또한 모든 타입을 직접 작성할 필요는 없다.

---

**5. 타입 추론**

초기값을 보고 TypeScript가 타입을 자동으로 판단할 수 있다.

```typescript
let age = 20;
```

`age`의 타입을 직접 작성하지 않아도 TypeScript는 `number`로 추론한다.

```typescript
age = "20";
```

이후 문자열을 넣으려고 하면 타입 오류를 확인할 수 있다.

```text
초기값
→ 타입 추론
→ 잘못된 타입 사용 검사
```

---

**6. 점진적 타입 시스템**

TypeScript의 타입 시스템은 **점진적 타입 시스템(Gradual Type System)**으로 설명할 수 있다.

```text
타입을 직접 지정
→ 명시한 타입 사용

타입을 생략
→ 초기값 등을 기준으로 타입 추론

실행 전
→ 타입 오류 검사
```

즉, 타입을 직접 작성할 수도 있고 TypeScript의 추론 기능을 활용할 수도 있다.

---

**7. JavaScript와 TypeScript 비교**

```text
JavaScript
→ 동적 타입
→ 유연함
→ 타입 오류를 런타임에 발견할 수 있음

TypeScript
→ 실행 전 타입 검사
→ 타입 추론 지원
→ 타입 관련 오류를 미리 발견
```

TypeScript의 핵심 장점은 **JavaScript의 유연함을 크게 유지하면서 타입 안전성을 높이는 것**이다.

---

**8. 핵심 정리**

* 타입 시스템은 타입을 결정하고 검사하는 규칙이다.
* JavaScript는 동적 타입 시스템을 사용한다.
* 동적 타입은 유연하지만 타입 오류를 실행 전에 찾기 어렵다.
* 정적 타입 시스템은 실행 전에 타입 오류를 발견할 수 있다.
* TypeScript도 코드를 실행하기 전에 타입을 검사한다.
* TypeScript는 타입을 모두 직접 작성하지 않아도 된다.
* 초기값 등을 이용해 타입을 자동으로 판단하는 것을 **타입 추론**이라고 한다.
* TypeScript의 타입 시스템은 **점진적 타입 시스템**으로 설명할 수 있다.
* 핵심은 **JavaScript의 유연함 + 정적 타입 검사의 안전성**이다.
