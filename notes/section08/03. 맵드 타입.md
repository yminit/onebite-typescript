# Section 8 - 3. 맵드 타입

**1. 맵드 타입이란?**

맵드 타입(Mapped Type)은 **기존 객체 타입을 기반으로 프로퍼티를 변환해 새로운 객체 타입을 만드는 기능**이다.

```text
기존 객체 타입
↓
프로퍼티 순회
↓
조건 변경
↓
새로운 객체 타입
```

기존 타입과 구조는 비슷하지만 선택 여부나 `readonly` 같은 조건이 다른 타입을 만들 때 유용하다.

---

**2. 기존 타입을 직접 복사하는 문제**

```ts
interface User {
  id: number;
  name: string;
  age: number;
}
```

사용자 정보를 일부만 수정하려면 모든 프로퍼티가 선택적인 타입이 필요할 수 있다.

```ts
interface PartialUser {
  id?: number;
  name?: string;
  age?: number;
}
```

이 방식은 `User`의 프로퍼티 이름과 타입을 다시 작성해야 한다.

```text
User
id: number
name: string
age: number

PartialUser
id?: number
name?: string
age?: number
```

즉, 타입 정보가 중복된다.

---

**3. 맵드 타입으로 만들기**

맵드 타입을 사용하면 기존 `User`를 이용해 `PartialUser`를 만들 수 있다.

```ts
type PartialUser = {
  [key in keyof User]?: User[key];
};
```

결과적으로 다음 타입과 같다.

```ts
type PartialUser = {
  id?: number;
  name?: string;
  age?: number;
};
```

---

**4. 맵드 타입 기본 구조**

핵심 문법은 다음과 같다.

```ts
type PartialUser = {
  [key in keyof User]?: User[key];
};
```

각 부분의 역할:

```text
keyof User
→ User의 모든 프로퍼티 키

key in keyof User
→ 각 키를 하나씩 순회

User[key]
→ 현재 key에 해당하는 프로퍼티 타입

?
→ 생성되는 프로퍼티를 선택적으로 만듦
```

---

**5. key in ...의 동작**

`keyof User`는 다음 타입이다.

```ts
"id" | "name" | "age"
```

맵드 타입은 이 키들을 하나씩 순회한다.

```text
key = "id"
key = "name"
key = "age"
```

각 키마다 새로운 프로퍼티를 생성한다.

---

**6. User[key]로 타입 가져오기**

각 프로퍼티의 타입은 인덱스드 액세스 타입으로 기존 `User`에서 가져온다.

```ts
User[key]
```

`key`가 `"id"`라면:

```ts
User["id"]
```

결과:

```ts
number
```

`key`가 `"name"`이라면:

```ts
User["name"]
```

결과:

```ts
string
```

즉, 기존 프로퍼티의 타입을 직접 반복해서 작성할 필요가 없다.

---

**7. PartialUser가 만들어지는 과정**

```ts
type PartialUser = {
  [key in keyof User]?: User[key];
};
```

내부적으로 다음처럼 이해할 수 있다.

```text
key = "id"
→ id?: User["id"]
→ id?: number

key = "name"
→ name?: User["name"]
→ name?: string

key = "age"
→ age?: User["age"]
→ age?: number
```

최종 결과:

```ts
type PartialUser = {
  id?: number;
  name?: string;
  age?: number;
};
```

---

**8. 일부 프로퍼티만 전달하기**

```ts
function updateUser(user: PartialUser) {
  // 사용자 정보 수정
}
```

필요한 값만 전달할 수 있다.

```ts
updateUser({
  age: 25,
});
```

또는:

```ts
updateUser({
  name: "홍길동",
  age: 30,
});
```

모든 프로퍼티가 선택적이기 때문이다.

---

**9. keyof를 함께 사용하는 이유**

다음처럼 키를 직접 작성할 수도 있다.

```ts
type PartialUser = {
  [key in "id" | "name" | "age"]?: User[key];
};
```

하지만 `User`에 프로퍼티가 추가되면 직접 수정해야 한다.

```ts
interface User {
  id: number;
  name: string;
  age: number;
  location: string;
}
```

`keyof User`를 사용하면 자동으로 반영된다.

```ts
type PartialUser = {
  [key in keyof User]?: User[key];
};
```

```text
User 변경
↓
keyof User 변경
↓
PartialUser도 자동 변경
```

---

**10. readonly 타입 만들기**

맵드 타입은 프로퍼티를 읽기 전용으로 바꾸는 데도 사용할 수 있다.

```ts
type ReadonlyUser = {
  readonly [key in keyof User]: User[key];
};
```

결과:

```ts
type ReadonlyUser = {
  readonly id: number;
  readonly name: string;
  readonly age: number;
};
```

---

**11. ReadonlyUser 사용하기**

```ts
const user: ReadonlyUser = {
  id: 1,
  name: "이정환",
  age: 27,
};
```

다음처럼 값을 다시 할당할 수 없다.

```ts
user.id = 2;
user.name = "홍길동";
user.age = 30;
```

모든 프로퍼티가 `readonly`이기 때문이다.

---

**12. 선택적 타입과 readonly 타입 비교**

선택적 프로퍼티:

```ts
type PartialUser = {
  [key in keyof User]?: User[key];
};
```

```text
id?: number
name?: string
age?: number
```

읽기 전용 프로퍼티:

```ts
type ReadonlyUser = {
  readonly [key in keyof User]: User[key];
};
```

```text
readonly id: number
readonly name: string
readonly age: number
```

즉, 맵드 타입을 이용하면 같은 기존 타입을 기반으로 서로 다른 조건의 타입을 만들 수 있다.

---

**13. 전체 코드**

```ts
interface User {
  id: number;
  name: string;
  age: number;
}

function fetchUser(): User {
  return {
    id: 1,
    name: "이정환",
    age: 27,
  };
}

type PartialUser = {
  [key in keyof User]?: User[key];
};

function updateUser(user: PartialUser) {
  // 사용자 정보 수정
}

updateUser({
  age: 25,
});

type ReadonlyUser = {
  readonly [key in keyof User]: User[key];
};

const user: ReadonlyUser = {
  id: 1,
  name: "이정환",
  age: 27,
};
```

---

**14. 핵심 정리**

* 맵드 타입은 기존 객체 타입을 기반으로 새로운 객체 타입을 만든다.
* `[key in keyof User]`는 `User`의 프로퍼티 키를 하나씩 순회한다.
* `User[key]`는 현재 프로퍼티의 타입을 기존 `User`에서 가져온다.
* `?`를 붙이면 모든 프로퍼티를 선택적으로 만들 수 있다.
* `readonly`를 붙이면 모든 프로퍼티를 읽기 전용으로 만들 수 있다.
* `keyof`와 함께 사용하면 기존 타입이 변경되어도 새 타입에 자동으로 반영된다.
* 타입을 직접 복사하지 않아 중복과 유지보수 문제를 줄일 수 있다.
* 핵심은 **`맵드 타입 = 기존 객체 타입의 key를 순회하면서 프로퍼티 조건을 바꿔 새로운 타입을 만드는 기능`**이다.
