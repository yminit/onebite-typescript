# Section 8 - 2. keyof & typeof 연산자

**1. keyof란?**

`keyof`는 **객체 타입이 가지고 있는 프로퍼티 키를 추출하는 연산자**이다.

```ts
interface Person {
  name: string;
  age: number;
}
```

```ts
type PersonKey = keyof Person;
```

결과:

```ts
"name" | "age"
```

즉:

```text
객체 타입
↓
keyof
↓
프로퍼티 키들의 Union 타입
```

---

**2. 프로퍼티 키를 직접 작성할 때의 문제**

다음 함수는 `Person`의 프로퍼티 값을 반환한다.

```ts
interface Person {
  name: string;
  age: number;
}

function getPropertyValue(
  person: Person,
  key: "name" | "age"
) {
  return person[key];
}
```

하지만 `Person`에 새로운 프로퍼티가 추가되면:

```ts
interface Person {
  name: string;
  age: number;
  location: string;
}
```

`key` 타입도 직접 수정해야 한다.

```ts
key: "name" | "age" | "location"
```

타입 정보를 중복해서 관리하게 된다.

---

**3. keyof로 키 타입 자동 생성하기**

```ts
interface Person {
  name: string;
  age: number;
  location: string;
}

function getPropertyValue(
  person: Person,
  key: keyof Person
) {
  return person[key];
}
```

`keyof Person`은 다음과 같다.

```ts
"name" | "age" | "location"
```

`Person`의 프로퍼티가 변경되면 `keyof Person`에도 자동으로 반영된다.

```text
Person 변경
↓
keyof Person 자동 변경
↓
키 타입을 따로 수정할 필요 없음
```

---

**4. 존재하는 키만 사용할 수 있다**

```ts
getPropertyValue(person, "name");
getPropertyValue(person, "age");
getPropertyValue(person, "location");
```

모두 `keyof Person`에 포함된 키이므로 사용할 수 있다.

반면:

```ts
getPropertyValue(person, "email");
```

`email`은 `Person`에 존재하지 않으므로 오류가 발생한다.

---

**5. keyof는 타입에 사용한다**

다음은 가능하다.

```ts
keyof Person
```

`Person`은 타입이기 때문이다.

반면 다음은 사용할 수 없다.

```ts
const person = {
  name: "이정환",
  age: 27,
};

// keyof person
```

`person`은 값이므로 타입 위치에서 직접 `keyof`의 대상으로 사용할 수 없다.

값으로부터 타입을 얻으려면 `typeof`를 사용한다.

---

**6. JavaScript의 typeof**

JavaScript에서 `typeof`는 실행 중에 값의 종류를 문자열로 확인한다.

```ts
const value = "hello";

console.log(typeof value);
```

결과:

```text
"string"
```

이 `typeof`는 **런타임 연산자**이다.

---

**7. TypeScript 타입 위치의 typeof**

TypeScript에서는 타입을 작성하는 위치에서 `typeof`를 사용하면 **값으로부터 타입을 추출**할 수 있다.

```ts
const person = {
  name: "이정환",
  age: 27,
  location: "서울",
};

type Person = typeof person;
```

`Person`은 다음과 같은 타입이 된다.

```ts
type Person = {
  name: string;
  age: number;
  location: string;
};
```

즉:

```text
person 값
↓
typeof person
↓
person의 타입
```

---

**8. 타입을 먼저 만들지 않고 값에서 추출하기**

기존 방식:

```ts
interface Person {
  name: string;
  age: number;
}

const person: Person = {
  name: "이정환",
  age: 27,
};
```

`typeof`를 사용하면 객체를 기준으로 타입을 만들 수도 있다.

```ts
const person = {
  name: "이정환",
  age: 27,
};

type Person = typeof person;
```

이미 존재하는 값의 구조를 그대로 타입으로 재사용하고 싶을 때 유용하다.

---

**9. keyof와 typeof 함께 사용하기**

값인 `person`의 프로퍼티 키를 타입으로 만들고 싶다면 다음처럼 사용한다.

```ts
const person = {
  name: "이정환",
  age: 27,
};

type PersonKey = keyof typeof person;
```

동작 순서:

```text
person
↓
typeof person
↓
{
  name: string;
  age: number;
}
↓
keyof
↓
"name" | "age"
```

즉:

```ts
type PersonKey = "name" | "age";
```

---

**10. 함수에 적용하기**

```ts
const person = {
  name: "이정환",
  age: 27,
};

type Person = typeof person;

function getPropertyValue(
  person: Person,
  key: keyof Person
) {
  return person[key];
}
```

사용:

```ts
getPropertyValue(person, "name");
getPropertyValue(person, "age");
```

다음은 오류가 발생한다.

```ts
getPropertyValue(person, "location");
```

현재 `person`에는 `location`이 없기 때문이다.

---

**11. 현재 함수 반환 타입의 특징**

다음 함수에서:

```ts
function getPropertyValue(
  person: Person,
  key: keyof Person
) {
  return person[key];
}
```

`key`는 다음 중 하나이다.

```ts
"name" | "age"
```

따라서 반환값도 가능한 프로퍼티 타입을 모두 포함한다.

```ts
string | number
```

즉:

```text
"name" 선택 → string
"age" 선택  → number

전체 반환 타입
→ string | number
```

특정 키에 맞춰 반환 타입까지 정확하게 연결하는 방법은 이후 제네릭과 인덱스드 액세스 타입을 함께 사용해 표현할 수 있다.

---

**12. keyof와 typeof의 역할**

```text
typeof 값
→ 값으로부터 타입 추출

keyof 객체타입
→ 객체 타입의 키 추출

keyof typeof 값
→ 값의 타입을 구한 뒤 그 타입의 키 추출
```

예:

```ts
const person = {
  name: "이정환",
  age: 27,
};

type Person = typeof person;
// { name: string; age: number }

type PersonKey = keyof typeof person;
// "name" | "age"
```

---

**13. keyof에 대한 주의점**

일반 객체의 문자열 프로퍼티에서는 보통 다음처럼 문자열 리터럴 Union으로 결과가 나온다.

```ts
"name" | "age"
```

하지만 `keyof`의 결과가 항상 문자열만 되는 것은 아니다.

TypeScript의 객체 키에는 `string`, `number`, `symbol`이 올 수 있기 때문이다.

현재 단계에서는 일반 객체에서 **프로퍼티 이름을 타입으로 추출한다**는 개념을 중심으로 이해하면 된다.

---

**14. 전체 코드**

```ts
const person = {
  name: "이정환",
  age: 27,
};

type Person = typeof person;

type PersonKey = keyof Person;

function getPropertyValue(
  person: Person,
  key: PersonKey
) {
  return person[key];
}

getPropertyValue(person, "name");
getPropertyValue(person, "age");
```

`keyof typeof`를 바로 사용할 수도 있다.

```ts
const person = {
  name: "이정환",
  age: 27,
};

function getPropertyValue(
  person: typeof person,
  key: keyof typeof person
) {
  return person[key];
}

getPropertyValue(person, "name");
getPropertyValue(person, "age");
```

---

**15. 핵심 정리**

* `keyof`는 객체 타입의 프로퍼티 키를 Union 타입으로 추출한다.
* `keyof Person`은 `Person`의 실제 프로퍼티 키만 허용한다.
* 객체 타입이 변경되면 `keyof`의 결과도 자동으로 변경된다.
* 따라서 `"name" | "age"`처럼 키를 직접 반복해서 작성할 필요가 없다.
* `keyof`는 타입을 대상으로 사용한다.
* JavaScript의 `typeof`는 런타임에서 값의 종류를 문자열로 확인한다.
* TypeScript의 타입 위치에서 사용하는 `typeof`는 값으로부터 타입을 추출한다.
* `typeof person`은 `person` 객체의 타입을 얻는다.
* `keyof typeof person`은 객체 값에서 타입을 얻은 뒤 그 타입의 키를 추출한다.
* `keyof`의 결과는 일반 객체에서는 문자열 리터럴 Union이 흔하지만 `number`나 `symbol` 키도 포함될 수 있다.
* 핵심은 **`typeof = 값 → 타입`, `keyof = 객체 타입 → 키 타입`**으로 기억하면 된다.
