# Section 8 - 1. 인덱스드 액세스 타입

**1. 인덱스드 액세스 타입이란?**

인덱스드 액세스 타입(Indexed Access Type)은 **다른 타입의 특정 프로퍼티나 요소 타입을 꺼내오는 문법**이다.

사용 대상:

```text
객체 타입
배열 타입
튜플 타입
```

기본 개념:

```text
기존 타입
↓
인덱스로 특정 위치 선택
↓
해당 위치의 타입 추출
```

---

**2. 객체 프로퍼티 타입 추출하기**

```ts
interface Post {
  title: string;
  content: string;
  author: {
    id: number;
    name: string;
    age: number;
  };
}
```

`author` 타입만 필요하다면:

```ts
type Author = Post["author"];
```

결과:

```ts
{
  id: number;
  name: string;
  age: number;
}
```

---

**3. 왜 직접 타입을 다시 작성하지 않을까?**

다음처럼 직접 작성할 수도 있다.

```ts
function printAuthorInfo(author: {
  id: number;
  name: string;
  age: number;
}) {
  console.log(`${author.id} - ${author.name}`);
}
```

하지만 `Post["author"]`를 사용하는 편이 타입 중복을 줄일 수 있다.

```ts
function printAuthorInfo(
  author: Post["author"]
) {
  console.log(`${author.id} - ${author.name}`);
}
```

`Post`의 `author` 구조가 변경되면 추출된 타입에도 자동으로 반영된다.

```text
Post["author"] 변경
↓
사용하는 모든 곳에 반영
```

---

**4. 인덱스에는 타입을 사용한다**

```ts
type Author = Post["author"];
```

여기서 `"author"`는 문자열 값처럼 보이지만 **문자열 리터럴 타입**이다.

다음처럼 일반 변수 자체를 타입 위치에 사용할 수는 없다.

```ts
const authorKey = "author";

type Author = Post[authorKey];
```

`authorKey`는 값이기 때문이다.

---

**5. typeof와 함께 사용하기**

값의 타입을 추출하면 인덱스로 사용할 수 있다.

```ts
const authorKey = "author";

type Author = Post[typeof authorKey];
```

`typeof authorKey`는 `"author"` 타입으로 추론되므로 다음과 같다.

```ts
type Author = Post["author"];
```

---

**6. 존재하는 키만 사용할 수 있다**

```ts
type Author = Post["author"];
```

`author`는 실제 프로퍼티이므로 가능하다.

반면:

```ts
type Wrong = Post["what"];
```

`what`이라는 프로퍼티가 없으므로 오류가 발생한다.

---

**7. 중첩해서 타입 추출하기**

객체 내부의 더 깊은 타입도 바로 추출할 수 있다.

```ts
type AuthorId =
  Post["author"]["id"];
```

결과:

```ts
number
```

이름 타입:

```ts
type AuthorName =
  Post["author"]["name"];
```

결과:

```ts
string
```

흐름:

```text
Post
↓
Post["author"]
↓
Post["author"]["id"]
↓
number
```

---

**8. 여러 프로퍼티 타입을 한 번에 추출하기**

인덱스에는 하나의 키만 사용할 필요가 없다.

```ts
type PostText =
  Post["title" | "content"];
```

결과:

```ts
string
```

서로 다른 타입이라면 Union 타입이 된다.

```ts
interface User {
  id: number;
  name: string;
}

type UserValue =
  User["id" | "name"];
```

결과:

```ts
number | string
```

---

**9. 배열 요소 타입 추출하기**

배열의 요소 타입은 `number`를 인덱스로 사용해 추출한다.

```ts
type PostList = {
  title: string;
  content: string;
  author: {
    id: number;
    name: string;
    age: number;
  };
}[];
```

게시글 하나의 타입:

```ts
type PostItem = PostList[number];
```

```text
PostList
→ 게시글 배열 타입

PostList[number]
→ 게시글 하나의 타입
```

---

**10. 배열 요소 내부 타입까지 추출하기**

```ts
type Author =
  PostList[number]["author"];
```

더 깊게 들어갈 수도 있다.

```ts
type AuthorId =
  PostList[number]["author"]["id"];
```

결과:

```ts
number
```

---

**11. 배열에 숫자 리터럴 인덱스 사용하기**

일반 배열 타입에서는 숫자 인덱스를 사용해도 요소 타입을 얻을 수 있다.

```ts
type Item1 = PostList[0];
type Item2 = PostList[1];
type Item3 = PostList[100];
```

모두 배열의 요소 타입이다.

```text
PostList[number]
PostList[0]
PostList[1]

→ 모두 같은 요소 타입
```

일반 배열은 특정 위치마다 다른 타입을 가지는 구조가 아니기 때문이다.

---

**12. 튜플 요소 타입 추출하기**

튜플에서는 각 위치에 정확한 타입이 정해져 있다.

```ts
type Tup = [
  number,
  string,
  boolean
];
```

각 위치의 타입:

```ts
type Tup0 = Tup[0];
// number

type Tup1 = Tup[1];
// string

type Tup2 = Tup[2];
// boolean
```

---

**13. 튜플은 존재하지 않는 위치에 접근할 수 없다**

```ts
type Tup = [
  number,
  string,
  boolean
];

type Tup3 = Tup[3];
```

네 번째 요소가 존재하지 않으므로 오류가 발생한다.

일반 배열과 달리 튜플은 길이와 각 위치의 타입이 정해져 있기 때문이다.

---

**14. Tup[number]**

튜플에 `number`를 인덱스로 사용하면 모든 요소 타입을 추출한다.

```ts
type Tup = [
  number,
  string,
  boolean
];

type TupValue = Tup[number];
```

결과:

```ts
number | string | boolean
```

즉:

```text
Tup[0] → number
Tup[1] → string
Tup[2] → boolean

Tup[number]
→ number | string | boolean
```

---

**15. 전체 코드**

```ts
interface Post {
  title: string;
  content: string;
  author: {
    id: number;
    name: string;
    age: number;
  };
}

function printAuthorInfo(
  author: Post["author"]
) {
  console.log(
    `${author.id} - ${author.name}`
  );
}

const post: Post = {
  title: "게시글 제목",
  content: "게시글 본문",
  author: {
    id: 1,
    name: "이정환",
    age: 27,
  },
};

printAuthorInfo(post.author);

type Author =
  Post["author"];

type AuthorId =
  Post["author"]["id"];

type PostList = Post[];

type PostItem =
  PostList[number];

type PostAuthor =
  PostList[number]["author"];

type PostAuthorId =
  PostList[number]["author"]["id"];

type Tup = [
  number,
  string,
  boolean
];

type Tup0 = Tup[0];
type Tup1 = Tup[1];
type Tup2 = Tup[2];

type TupValue =
  Tup[number];
```

---

**16. 핵심 정리**

* 인덱스드 액세스 타입은 기존 타입에서 특정 부분의 타입을 추출한다.
* 객체는 `Type["key"]` 형태로 프로퍼티 타입을 가져온다.
* `Post["author"]`는 `author` 프로퍼티의 타입이다.
* 인덱스에는 값이 아니라 타입을 사용한다.
* 값으로부터 인덱스 타입이 필요하면 `typeof`를 함께 사용할 수 있다.
* 존재하지 않는 프로퍼티는 인덱스로 사용할 수 없다.
* `Post["author"]["id"]`처럼 중첩해서 사용할 수 있다.
* 여러 키를 Union으로 전달하면 여러 프로퍼티의 값 타입을 한 번에 추출할 수 있다.
* 배열의 요소 타입은 `ArrayType[number]`로 추출한다.
* 튜플은 `Tuple[0]`처럼 위치별 정확한 타입을 가져올 수 있다.
* `Tuple[number]`는 튜플의 모든 요소 타입을 Union으로 만든다.
* 핵심은 **`인덱스드 액세스 타입 = 이미 정의된 타입에서 필요한 부분의 타입만 재사용하는 기능`**이다.
