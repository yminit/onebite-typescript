# Section 4 - 4. 사용자 정의 타입 가드

**1. 사용자 정의 타입 가드란?**

사용자 정의 타입 가드는 **특정 값이 어떤 타입인지 판별하는 함수를 직접 만드는 방법**이다.

예를 들어 다음 두 타입이 있다고 하자.

```ts
type Dog = {
  name: string;
  isBark: boolean;
};

type Cat = {
  name: string;
  isScratch: boolean;
};

type Animal = Dog | Cat;
```

`Animal`은 `Dog` 또는 `Cat`이다.

---

**2. 기존 방식으로 타입 좁히기**

`in` 연산자를 사용하면 특정 프로퍼티가 있는지 확인할 수 있다.

```ts
function warning(animal: Animal) {
  if ("isBark" in animal) {
    // animal: Dog
  } else {
    // animal: Cat
  }
}
```

이 방식도 정상적으로 동작한다.

하지만 여러 곳에서 같은 검사를 반복하면 타입 판별 로직이 중복될 수 있다.

---

**3. 타입 검사 로직을 함수로 분리하기**

다음처럼 `Dog`인지 확인하는 함수를 만들 수 있다.

```ts
function isDog(animal: Animal) {
  return "isBark" in animal;
}
```

하지만 반환 타입이 단순한 `boolean`이면 TypeScript는 이 함수의 `true`가 정확히 무엇을 의미하는지 알 수 없다.

```text
true
→ Dog라는 의미인지 TypeScript가 알 수 없음
```

그래서 **타입 프레디케이트**가 필요하다.

---

**4. 타입 프레디케이트**

사용자 정의 타입 가드의 반환 타입에는 다음 문법을 사용할 수 있다.

```ts
매개변수이름 is 타입
```

예:

```ts
function isDog(animal: Animal): animal is Dog {
  return "isBark" in animal;
}
```

`animal is Dog`는 다음 의미다.

```text
isDog(animal) === true
↓
animal은 Dog 타입
```

---

**5. 사용자 정의 타입 가드 사용하기**

```ts
function warning(animal: Animal) {
  if (isDog(animal)) {
    console.log(animal.isBark);
  } else {
    console.log(animal.isScratch);
  }
}
```

`isDog(animal)`이 `true`이면:

```text
Animal
↓
Dog
```

반대로 `false`이면 현재 Union에서 남은 타입인 `Cat`으로 좁혀진다.

```text
Animal
↓
Cat
```

---

**6. 전체 흐름**

```text
Animal
: Dog | Cat
↓
isDog(animal)
↓
true
→ Dog

false
→ Cat
```

사용자 정의 타입 가드는 결국 **타입 좁히기 로직에 이름을 붙여 함수로 분리한 것**이라고 이해하면 된다.

---

**7. 기존 방식과 비교**

직접 검사:

```ts
if ("isBark" in animal) {
  // Dog
}
```

사용자 정의 타입 가드:

```ts
if (isDog(animal)) {
  // Dog
}
```

두 번째 방식은 조건의 의미가 더 직접적으로 드러난다.

```text
"isBark" in animal
→ 프로퍼티 구조를 알아야 의미 파악

isDog(animal)
→ Dog인지 검사한다는 의미가 바로 보임
```

또한 같은 판별 로직을 여러 곳에서 재사용할 수 있다.

---

**8. 타입 프레디케이트에서 주의할 점**

```ts
function isDog(animal: Animal): animal is Dog {
  return "isBark" in animal;
}
```

`animal is Dog`라고 작성했다고 해서 TypeScript가 함수 내부 구현까지 완벽하게 검증해 주는 것은 아니다.

예를 들어 잘못 작성해도:

```ts
function isDog(animal: Animal): animal is Dog {
  return "isScratch" in animal;
}
```

개발자가 `Dog`라고 선언했기 때문에 호출부에서는 잘못 좁혀질 수 있다.

따라서 사용자 정의 타입 가드의 **판별 로직과 타입 프레디케이트가 실제로 일치해야 한다.**

---

**9. 전체 코드**

```ts
type Dog = {
  name: string;
  isBark: boolean;
};

type Cat = {
  name: string;
  isScratch: boolean;
};

type Animal = Dog | Cat;

function isDog(animal: Animal): animal is Dog {
  return "isBark" in animal;
}

function warning(animal: Animal) {
  if (isDog(animal)) {
    if (animal.isBark) {
      console.log("짖습니다.");
    } else {
      console.log("안 짖어요.");
    }
  } else {
    if (animal.isScratch) {
      console.log("할큅니다.");
    } else {
      console.log("안 할퀴어요.");
    }
  }
}
```

---

**10. 핵심 정리**

* 사용자 정의 타입 가드는 타입을 판별하는 함수를 직접 만드는 방법이다.
* 반환 타입에 **타입 프레디케이트**를 사용한다.
* 타입 프레디케이트는 `매개변수 is 타입` 형태로 작성한다.
* `animal is Dog`는 함수가 `true`를 반환했을 때 `animal`을 `Dog`로 좁힌다는 의미다.
* 사용자 정의 타입 가드를 사용하면 타입 판별 로직을 함수로 분리하고 재사용할 수 있다.
* `in` 연산자를 직접 반복해서 사용하는 것보다 의미를 명확하게 표현할 수 있다.
* 타입 프레디케이트는 개발자가 작성한 판별 결과를 TypeScript가 신뢰하므로 구현을 정확하게 작성해야 한다.
* 핵심은 **`boolean 판별 함수 + 타입 프레디케이트 = 사용자 정의 타입 가드`**이다.
