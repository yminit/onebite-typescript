# Section 4 - 2. 함수 타입의 호환성

**1. 함수 타입의 호환성**

함수 타입의 호환성은 **한 함수 타입을 다른 함수 타입으로 취급할 수 있는지** 판단하는 것이다.

확인할 것은 두 가지다.

```text
1. 반환값 타입
2. 매개변수 타입
```

둘 다 호환되어야 한다.

---

**2. 반환값 타입의 호환성**

```ts
type A = () => number;
type B = () => 10;
```

`10`은 `number`의 서브 타입이다.

따라서 `B` 타입 함수는 `A` 타입으로 취급할 수 있다.

```ts
let a: A = () => 10;
let b: B = () => 10;

a = b;
```

```text
10
↓
number

서브 타입 → 슈퍼 타입
→ 가능
```

반대는 불가능하다.

```ts
b = a;
```

`A` 타입 함수는 `10`이 아닌 다른 숫자를 반환할 수도 있기 때문이다.

---

**3. 반환값은 일반적인 타입 호환성과 같은 방향**

```text
함수가 실제로 반환하는 타입
↓
할당받는 함수 타입이 기대하는 반환 타입
```

서브 타입을 반환하는 함수는 슈퍼 타입을 반환하는 함수로 취급할 수 있다.

```text
() => 10
↓
() => number
```

이를 **공변적(covariant)**이라고 표현하기도 한다.

---

**4. 매개변수 타입의 호환성**

매개변수는 반환값과 반대 방향으로 생각해야 한다.

```ts
type C = (value: number) => void;
type D = (value: 10) => void;
```

```ts
let c: C = (value) => {};
let d: D = (value) => {};

d = c;
```

가능하다.

`c`는 모든 `number`를 받을 수 있으므로 당연히 `10`도 받을 수 있다.

---

**5. 반대 방향은 위험하다**

```ts
c = d;
```

이 할당은 안전하지 않다.

`c`는 다음처럼 호출될 수 있다.

```ts
c(10);
c(20);
c(100);
```

하지만 실제 함수가 `D`라면 `10`만 받을 수 있다고 정의되어 있다.

```text
(number) => void
←
(10) => void

안전하지 않음
```

---

**6. 매개변수 타입은 반대 방향**

정리하면:

```text
반환값
서브 타입 → 슈퍼 타입

매개변수
슈퍼 타입을 받는 함수 → 서브 타입을 받는 함수 타입
```

즉, 더 넓은 범위의 값을 처리할 수 있는 함수가 더 안전하다.

---

**7. 객체 타입으로 이해하기**

```ts
type Animal = {
  name: string;
};

type Dog = {
  name: string;
  color: string;
};
```

`Animal`은 `Dog`의 슈퍼 타입이다.

```text
Animal
↑
Dog
```

함수:

```ts
const animalFunc = (animal: Animal) => {
  console.log(animal.name);
};

const dogFunc = (dog: Dog) => {
  console.log(dog.name);
  console.log(dog.color);
};
```

---

**8. Animal을 받는 함수는 Dog 자리에서 사용 가능**

```ts
dogFunc = animalFunc;
```

`Dog` 객체는 반드시 `name`을 가지고 있다.

그리고 실제 실행되는 `animalFunc`는 `name`만 사용한다.

```text
Dog 객체
├─ name
└─ color

animalFunc가 필요한 것
└─ name
```

따라서 안전하다.

---

**9. Dog만 받는 함수는 Animal 자리에서 사용 불가**

```ts
animalFunc = dogFunc;
```

`Animal`에는 `color`가 있다는 보장이 없다.

그런데 실제로 실행될 `dogFunc`는 `color`를 사용한다.

```text
Animal
└─ name

dogFunc
├─ name 필요
└─ color 필요
```

따라서 안전하지 않다.

---

**10. 매개변수 개수가 다른 경우**

```ts
type Func1 = (a: number, b: number) => void;
type Func2 = (a: number) => void;
```

매개변수가 적은 함수는 더 많은 매개변수를 받는 함수 타입에 할당할 수 있다.

```ts
let func1: Func1 = (a, b) => {};
let func2: Func2 = (a) => {};

func1 = func2;
```

호출 시:

```ts
func1(1, 2);
```

실제로 실행되는 `func2`는 두 번째 인수를 사용하지 않아도 된다.

---

**11. 반대 방향은 불가능**

```ts
func2 = func1;
```

`func2`는 인수 하나만 전달받는다고 기대된다.

```ts
func2(1);
```

하지만 실제 함수 `func1`은 두 번째 매개변수까지 필요하다.

따라서 안전하지 않다.

---

**12. 전체 규칙**

```text
함수 타입 호환성
│
├─ 반환값
│  └─ 서브 타입 → 슈퍼 타입
│
├─ 매개변수 타입
│  └─ 더 넓은 타입을 받는 함수가 더 안전
│
└─ 매개변수 개수
   └─ 적은 매개변수를 사용하는 함수가 더 유연
```

---

**13. 핵심 정리**

* 함수 타입의 호환성은 **반환값과 매개변수 타입**을 모두 본다.
* 반환값은 일반적인 타입 호환성과 같은 방향으로 검사한다.
* `() => 10`은 `() => number`로 취급할 수 있다.
* 매개변수 타입은 반환값과 반대 방향으로 판단한다.
* `(number) => void`는 `(10) => void` 자리에서 사용할 수 있다.
* 더 넓은 타입을 받을 수 있는 함수가 더 안전하다.
* `Animal`을 받는 함수는 `Dog`를 받는 함수 타입으로 취급할 수 있다.
* `Dog`만 받는 함수는 `Animal`을 받는 함수 타입으로 취급할 수 없다.
* 매개변수 개수가 적은 함수는 더 많은 매개변수를 받는 함수 타입에 할당할 수 있다.
* 핵심은 **반환값은 “무엇을 내보내는가”, 매개변수는 “무엇까지 받아낼 수 있는가”를 기준으로 안전성을 판단하는 것**이다.
