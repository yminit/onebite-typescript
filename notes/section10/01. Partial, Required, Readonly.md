# Section 10 - 1. Partial, Required, Readonly

**1. 이번 시간의 핵심**

`Partial`, `Required`, `Readonly`는 **맵드 타입을 기반으로 기존 객체 타입의 프로퍼티 조건을 바꾸는 유틸리티 타입**이다.

```text
Partial<T>
→ 모두 선택적

Required<T>
→ 모두 필수

Readonly<T>
→ 모두 읽기 전용
```

---

**2. 기준이 되는 Post 타입**

```ts
interface Post {
  title: string;
  tags: string[];
  content: string;
  thumbnailURL?: string;
}
```

여기서 `thumbnailURL`만 선택적 프로퍼티이다.

---

**3. Partial<T>**

`Partial<T>`는 `T`의 모든 프로퍼티를 선택적으로 만든다.

```ts
type PartialPost = Partial<Post>;
```

결과:

```ts
type PartialPost = {
  title?: string;
  tags?: string[];
  content?: string;
  thumbnailURL?: string;
};
```

따라서 임시 저장처럼 일부 정보만 있는 객체에 사용할 수 있다.

```ts
const draft: Partial<Post> = {
  title: "제목 나중에 짓자",
  content: "초안...",
};
```

---

**4. Partial을 직접 구현하면**

```ts
type MyPartial<T> = {
  [K in keyof T]?: T[K];
};
```

동작:

```text
keyof T
→ T의 모든 키 추출

K in keyof T
→ 각 키 순회

T[K]
→ 기존 프로퍼티 타입 가져오기

?
→ 선택적 프로퍼티로 변경
```

`Post`에 적용하면:

```text
title        → title?
tags         → tags?
content      → content?
thumbnailURL → thumbnailURL?
```

---

**5. Required<T>**

`Required<T>`는 `T`의 모든 프로퍼티를 필수로 만든다.

```ts
type RequiredPost = Required<Post>;
```

결과:

```ts
type RequiredPost = {
  title: string;
  tags: string[];
  content: string;
  thumbnailURL: string;
};
```

사용:

```ts
const withThumbnailPost: Required<Post> = {
  title: "한입 타스 후기",
  tags: ["ts"],
  content: "",
  thumbnailURL: "https://...",
};
```

이제 `thumbnailURL`도 반드시 필요하다.

---

**6. Required를 직접 구현하면**

```ts
type MyRequired<T> = {
  [K in keyof T]-?: T[K];
};
```

핵심은 `-?`이다.

```text
?
→ 선택적 속성 추가

-?
→ 선택적 속성 제거
```

예:

```text
thumbnailURL?: string
↓
thumbnailURL: string
```

이미 필수인 프로퍼티는 그대로 유지된다.

---

**7. Readonly<T>**

`Readonly<T>`는 `T`의 모든 프로퍼티를 읽기 전용으로 만든다.

```ts
type ReadonlyPost = Readonly<Post>;
```

결과:

```ts
type ReadonlyPost = {
  readonly title: string;
  readonly tags: string[];
  readonly content: string;
  readonly thumbnailURL?: string;
};
```

사용:

```ts
const readonlyPost: Readonly<Post> = {
  title: "보호된 게시글입니다.",
  tags: [],
  content: "",
};
```

다음과 같은 재할당은 불가능하다.

```ts
readonlyPost.content = "변경";
```

---

**8. Readonly를 직접 구현하면**

```ts
type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};
```

`T`의 모든 프로퍼티 앞에 `readonly`를 붙인다.

```text
title
→ readonly title

tags
→ readonly tags

content
→ readonly content
```

---

**9. 세 유틸리티 타입 비교**

```text
Partial<T>
→ 프로퍼티를 생략할 수 있게 만듦

Required<T>
→ 프로퍼티를 반드시 작성하게 만듦

Readonly<T>
→ 프로퍼티 재할당을 막음
```

구현만 비교하면 더 쉽게 보인다.

```ts
type MyPartial<T> = {
  [K in keyof T]?: T[K];
};

type MyRequired<T> = {
  [K in keyof T]-?: T[K];
};

type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};
```

차이는 프로퍼티에 어떤 수정자를 적용하느냐이다.

---

**10. 주의: Readonly는 얕게 적용된다**

다음 타입을 보자.

```ts
type ReadonlyPost = Readonly<Post>;
```

`tags` 프로퍼티 자체를 다른 배열로 교체할 수는 없다.

```ts
readonlyPost.tags = ["react"];
```

하지만 `Readonly<Post>`는 중첩된 값까지 자동으로 깊게 읽기 전용으로 만드는 타입은 아니다.

즉, `readonly`가 **프로퍼티 자체에 적용된다는 점**을 기억하면 된다.

---

**11. 전체 코드**

```ts
interface Post {
  title: string;
  tags: string[];
  content: string;
  thumbnailURL?: string;
}

const draft: Partial<Post> = {
  title: "제목 나중에 짓자",
  content: "초안...",
};

const withThumbnailPost: Required<Post> = {
  title: "한입 타스 후기",
  tags: ["ts"],
  content: "",
  thumbnailURL: "https://...",
};

const readonlyPost: Readonly<Post> = {
  title: "보호된 게시글입니다.",
  tags: [],
  content: "",
};

// 오류
// readonlyPost.content = "변경";

type MyPartial<T> = {
  [K in keyof T]?: T[K];
};

type MyRequired<T> = {
  [K in keyof T]-?: T[K];
};

type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};
```

---

**12. 핵심 정리**

* `Partial<T>`는 모든 프로퍼티를 선택적으로 만든다.
* 임시 저장이나 일부 정보만 전달하는 객체에 활용할 수 있다.
* `Partial`은 맵드 타입에서 `?`를 붙여 구현한다.
* `Required<T>`는 모든 프로퍼티를 필수로 만든다.
* `Required`는 `-?`를 사용해 선택적 속성을 제거한다.
* `Readonly<T>`는 모든 프로퍼티를 읽기 전용으로 만든다.
* `Readonly`는 `readonly` 수정자를 맵드 타입에 추가해 구현한다.
* 세 타입 모두 `keyof T`, `K in keyof T`, `T[K]` 구조를 사용한다.
* 핵심은 **`같은 객체 구조를 유지하면서 프로퍼티의 선택 여부와 수정 가능 여부만 바꾸는 것`**이다.
