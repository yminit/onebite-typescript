# Section 10 - 2. Record, Pick, Omit

이번 시간에는 객체 타입을 **선택하고, 제외하고, 새로 구성하는** 세 가지 유틸리티 타입을 다룬다.

**1. 기준이 되는 Post 타입**

```ts id="u3k0jn"
interface Post {
  title: string;
  tags: string[];
  content: string;
  thumbnailURL?: string;
}
```

---

**2. Pick<T, K>**

`Pick<T, K>`는 객체 타입 `T`에서 **필요한 프로퍼티 `K`만 골라 새로운 타입을 만든다.**

```ts id="dhjn0j"
type LegacyPost = Pick<
  Post,
  "title" | "content"
>;
```

결과:

```ts id="7ufd1f"
type LegacyPost = {
  title: string;
  content: string;
};
```

사용:

```ts id="nz29px"
const legacyPost: LegacyPost = {
  title: "옛날 글",
  content: "옛날 콘텐츠",
};
```

---

**3. Pick 직접 구현하기**

```ts id="d2bypg"
type MyPick<
  T,
  K extends keyof T
> = {
  [P in K]: T[P];
};
```

각 부분의 의미:

```text id="3rfeh8"
T
→ 원본 객체 타입

K
→ 선택할 프로퍼티 키

K extends keyof T
→ T에 실제로 존재하는 키만 허용

[P in K]
→ 선택한 키 순회

T[P]
→ 원래 프로퍼티 타입 가져오기
```

예:

```ts id="gefe2c"
type Result = MyPick<
  Post,
  "title" | "content"
>;
```

---

**4. 왜 K extends keyof T가 필요한가?**

`K`에는 `Post`에 실제 존재하는 키만 들어가야 한다.

```ts id="jhquwq"
type A = Pick<Post, "title">;
```

가능하다.

하지만:

```ts id="as55rd"
type B = Pick<Post, "author">;
```

`author`는 `Post`에 존재하지 않으므로 사용할 수 없다.

---

**5. Omit<T, K>**

`Omit<T, K>`는 객체 타입 `T`에서 **지정한 프로퍼티 `K`를 제외한 타입을 만든다.**

```ts id="2ywd3e"
type NoTitlePost =
  Omit<Post, "title">;
```

결과:

```ts id="zpt86v"
type NoTitlePost = {
  tags: string[];
  content: string;
  thumbnailURL?: string;
};
```

사용:

```ts id="1kce9q"
const noTitlePost: NoTitlePost = {
  tags: [],
  content: "",
  thumbnailURL: "",
};
```

---

**6. 여러 프로퍼티 제외하기**

두 번째 타입 인수에 Union 타입을 전달하면 여러 프로퍼티를 제외할 수 있다.

```ts id="kyh3k6"
type SimplePost = Omit<
  Post,
  "tags" | "thumbnailURL"
>;
```

결과:

```ts id="pbwr0e"
type SimplePost = {
  title: string;
  content: string;
};
```

---

**7. Omit 직접 구현하기**

`Omit`은 다음 순서로 이해하면 쉽다.

```text id="dqzawo"
1. keyof T
→ 모든 키 추출

2. Exclude<keyof T, K>
→ 제외할 키 제거

3. Pick<T, ...>
→ 남은 키만 선택
```

구현:

```ts id="h8akru"
type MyOmit<
  T,
  K extends keyof T
> = Pick<
  T,
  Exclude<keyof T, K>
>;
```

예:

```ts id="28fmpp"
type Result =
  MyOmit<Post, "title">;
```

계산:

```text id="hf6hxq"
keyof Post
→ "title" | "tags" | "content" | "thumbnailURL"

Exclude<..., "title">
→ "tags" | "content" | "thumbnailURL"

Pick<Post, ...>
→ title을 제외한 객체 타입
```

---

**8. Pick과 Omit의 차이**

```text id="jkhb8q"
Pick<T, K>
→ 필요한 것만 선택

Omit<T, K>
→ 필요 없는 것을 제거
```

예:

```ts id="bw7pqo"
type A = Pick<
  Post,
  "title" | "content"
>;

type B = Omit<
  Post,
  "tags" | "thumbnailURL"
>;
```

두 타입의 결과는 같다.

```ts id="mmdsro"
type Result = {
  title: string;
  content: string;
};
```

---

**9. Record<K, V>**

`Record<K, V>`는 **키가 `K`, 값 타입이 `V`인 객체 타입을 만든다.**

예를 들어 썸네일 크기별 URL을 표현해보자.

```ts id="ppqa3u"
type Thumbnail = Record<
  "large" | "medium" | "small" | "watch",
  {
    url: string;
  }
>;
```

결과:

```ts id="p80i0p"
type Thumbnail = {
  large: {
    url: string;
  };
  medium: {
    url: string;
  };
  small: {
    url: string;
  };
  watch: {
    url: string;
  };
};
```

---

**10. Record 사용하기**

```ts id="w6s3iy"
const thumbnail: Thumbnail = {
  large: {
    url: "https://...",
  },
  medium: {
    url: "https://...",
  },
  small: {
    url: "https://...",
  },
  watch: {
    url: "https://...",
  },
};
```

첫 번째 타입 인수에 지정한 키는 모두 작성해야 한다.

```text id="tgg8eq"
large
medium
small
watch
```

각 프로퍼티의 값은 모두 두 번째 타입 인수의 구조를 따라야 한다.

---

**11. Record 직접 구현하기**

```ts id="riyp0u"
type MyRecord<
  K extends keyof any,
  V
> = {
  [P in K]: V;
};
```

역할:

```text id="qxqk4b"
K
→ 객체의 키 타입

V
→ 각 프로퍼티 값 타입

[P in K]
→ K의 키를 하나씩 순회

V
→ 모든 프로퍼티 값에 같은 타입 적용
```

---

**12. keyof any**

객체의 프로퍼티 키로 사용할 수 있는 타입은 다음과 같다.

```ts id="hntqv1"
string | number | symbol
```

`keyof any`도 같은 타입이다.

```ts id="0zzkwe"
type Key =
  keyof any;
// string | number | symbol
```

그래서 `Record`의 `K`를 다음처럼 제한할 수 있다.

```ts id="6hxzfw"
K extends keyof any
```

---

**13. 세 유틸리티 타입 비교**

```text id="o7p4jb"
Pick<T, K>
→ 기존 타입에서 필요한 프로퍼티만 선택

Omit<T, K>
→ 기존 타입에서 지정한 프로퍼티 제거

Record<K, V>
→ K를 키로 하고 V를 값 타입으로 하는
  새로운 객체 타입 생성
```

---

**14. 구현 비교**

```ts id="s7s5i4"
type MyPick<
  T,
  K extends keyof T
> = {
  [P in K]: T[P];
};

type MyOmit<
  T,
  K extends keyof T
> = Pick<
  T,
  Exclude<keyof T, K>
>;

type MyRecord<
  K extends keyof any,
  V
> = {
  [P in K]: V;
};
```

구조를 보면 차이가 명확하다.

```text id="08qr16"
Pick
→ K를 순회하며 T[P] 사용

Omit
→ 제외할 키를 제거한 뒤 Pick

Record
→ K를 순회하며 모든 값 타입을 V로 지정
```

---

**15. 전체 코드**

```ts id="4zqi28"

  title: string;
  tags: string[];
  content: string;
  thumbnailURL?: string;
}

const legacyPost: Pick<
  Post,
  "title" | "content"
> = {
  title: "옛날 글",
  content: "옛날 콘텐츠",
};

const noTitlePost: Omit<
  Post,
  "title"
> = {
  tags: [],
  content: "",
  thumbnailURL: "",
};

type Thumbnail = Record<
  "large" | "medium" | "small" | "watch",
  {
    url: string;
  }
>;

const thumbnail: Thumbnail = {
  large: {
    url: "https://...",
  },
  medium: {
    url: "https://...",
  },
  small: {
    url: "https://...",
  },
  watch: {
    url: "https://...",
  },
};

type MyPick<
  T,
  K extends keyof T
> = {
  [P in K]: T[P];
};

type MyOmit<
  T,
  K extends keyof T
> = Pick<
  T,
  Exclude<keyof T, K>
>;

type MyRecord<
  K extends keyof any,
  V
> = {
  [P in K]: V;
};
```

**16. 핵심 정리**

* `Pick<T, K>`는 `T`에서 `K`에 해당하는 프로퍼티만 선택한다.
* `K extends keyof T`를 사용해 실제 존재하는 키만 허용한다.
* `Pick`은 맵드 타입과 인덱스드 액세스 타입으로 구현할 수 있다.
* `Omit<T, K>`는 `T`에서 `K`에 해당하는 프로퍼티를 제거한다.
* `Omit`은 `Exclude`로 키를 제거한 뒤 `Pick`으로 남은 프로퍼티를 선택하는 방식으로 이해할 수 있다.
* `Pick`은 **선택**, `Omit`은 **제외**이다.
* `Record<K, V>`는 `K`를 프로퍼티 키로 사용하고 모든 값의 타입을 `V`로 만드는 객체 타입이다.
* `keyof any`는 `string | number | symbol`이다.
* 핵심은 **`Pick = 고르기`, `Omit = 빼기`, `Record = 키와 값 타입으로 새 객체 만들기`**이다.
