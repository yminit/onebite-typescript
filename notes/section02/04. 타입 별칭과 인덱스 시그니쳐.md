# Section 2 - 4. 타입 별칭과 인덱스 시그니처

**1. 타입 별칭**

타입 별칭은 **타입에 이름을 붙여 재사용하는 문법**이다.

기본 형태:

```ts
type 타입이름 = 타입;
```

예:

```ts
type User = {
  id: number;
  name: string;
  nickname: string;
  birth: string;
  bio: string;
  location: string;
};
```

이후 같은 타입을 반복해서 작성하지 않고 사용할 수 있다.

```ts
const user: User = {
  id: 1,
  name: "이정환",
  nickname: "winterlood",
  birth: "1997.01.07",
  bio: "안녕하세요",
  location: "부천시",
};
```

---

**2. 타입 별칭을 사용하는 이유**

객체 타입을 매번 직접 작성하면 코드가 길어지고 중복이 생긴다.

```text
객체 타입 반복 작성
→ 코드 중복 증가

타입 별칭 사용
→ 한 번 정의
→ 여러 곳에서 재사용
```

예:

```ts
let user1: User;
let user2: User;
let user3: User;
```

---

**3. 타입 별칭과 스코프**

같은 스코프에서는 같은 이름의 타입 별칭을 중복 선언할 수 없다.

```ts
type User = {
  id: number;
};

// 오류
type User = string;
```

하지만 서로 다른 스코프라면 같은 이름을 사용할 수 있다.

```ts
type User = {
  id: number;
};

function test() {
  type User = string;
}
```

각 스코프의 `User`는 서로 다른 타입이다.

---

**4. 타입 별칭은 컴파일 후 사라진다**

타입 별칭은 TypeScript의 **타입 검사에만 사용되는 문법**이다.

```ts
type User = {
  id: number;
  name: string;
};

const user: User = {
  id: 1,
  name: "이정환",
};
```

JavaScript로 컴파일되면 타입 정보는 제거된다.

```js
const user = {
  id: 1,
  name: "이정환",
};
```

---

**5. 인덱스 시그니처**

인덱스 시그니처는 **이름을 미리 알 수 없는 여러 프로퍼티가 일정한 타입 규칙을 따를 때** 사용한다.

예:

```ts
type CountryCodes = {
  [key: string]: string;
};
```

의미:

```text
프로퍼티 키
→ string

프로퍼티 값
→ string
```

따라서 다음 객체를 표현할 수 있다.

```ts
const countryCodes: CountryCodes = {
  Korea: "ko",
  UnitedState: "us",
  UnitedKingdom: "uk",
};
```

프로퍼티 이름을 타입에 하나씩 작성할 필요가 없다.

---

**6. 인덱스 시그니처 기본 형태**

```ts
{
  [key: 키타입]: 값타입;
}
```

예를 들어 문자열 키와 숫자 값을 가진 객체:

```ts
type CountryNumberCodes = {
  [key: string]: number;
};
```

사용:

```ts
const countryNumberCodes: CountryNumberCodes = {
  Korea: 410,
  UnitedState: 840,
  UnitedKingdom: 826,
};
```

---

**7. 필수 프로퍼티 함께 사용하기**

인덱스 시그니처를 사용하면서 특정 프로퍼티를 반드시 요구할 수도 있다.

```ts
type CountryNumberCodes = {
  [key: string]: number;
  Korea: number;
};
```

이 경우 `Korea`는 반드시 존재해야 한다.

```ts
const countryNumberCodes: CountryNumberCodes = {
  Korea: 410,
  UnitedState: 840,
};
```

---

**8. 직접 선언한 프로퍼티의 타입 규칙**

인덱스 시그니처와 함께 선언한 프로퍼티도 해당 규칙을 만족해야 한다.

```ts
type CountryNumberCodes = {
  [key: string]: number;
  Korea: number;
};
```

`Korea`도 문자열 키이므로 값은 `number`여야 한다.

다음은 허용되지 않는다.

```ts
type CountryNumberCodes = {
  [key: string]: number;

  // 오류
  Korea: string;
};
```

```text
[key: string]: number
→ 모든 문자열 키의 값은 number여야 함
```

---

**9. 타입 별칭과 인덱스 시그니처의 역할**

```text
타입 별칭
→ 타입 자체에 이름을 붙여 재사용

인덱스 시그니처
→ 규칙이 같은 여러 프로퍼티를 한 번에 표현
```

둘은 서로 대체하는 문법이 아니라 함께 사용할 수 있다.

```ts
type CountryCodes = {
  [key: string]: string;
};
```

여기서:

```text
CountryCodes
→ 타입 별칭

[key: string]: string
→ 인덱스 시그니처
```

---

**10. 핵심 코드**

```ts
type User = {
  id: number;
  name: string;
  nickname: string;
  birth: string;
  bio: string;
  location: string;
};

const user: User = {
  id: 1,
  name: "이정환",
  nickname: "winterlood",
  birth: "1997.01.07",
  bio: "안녕하세요",
  location: "부천시",
};

type CountryCodes = {
  [key: string]: string;
};

const countryCodes: CountryCodes = {
  Korea: "ko",
  UnitedState: "us",
  UnitedKingdom: "uk",
};

type CountryNumberCodes = {
  [key: string]: number;
  Korea: number;
};

const countryNumberCodes: CountryNumberCodes = {
  Korea: 410,
  UnitedState: 840,
  UnitedKingdom: 826,
};
```

---

**11. 핵심 정리**

* 타입 별칭은 `type 이름 = 타입` 형태로 작성한다.
* 같은 타입을 여러 곳에서 재사용할 때 유용하다.
* 같은 스코프에서는 같은 이름의 타입 별칭을 중복 선언할 수 없다.
* 타입 별칭은 타입 문법이므로 JavaScript로 컴파일될 때 사라진다.
* 인덱스 시그니처는 **프로퍼티 이름은 다양하지만 값의 타입 규칙이 같은 객체**를 표현할 때 사용한다.
* `[key: string]: string`은 문자열 키에 문자열 값이 들어간다는 의미이다.
* 특정 프로퍼티를 필수로 추가할 수도 있다.
* 직접 선언한 프로퍼티 역시 인덱스 시그니처의 값 타입과 호환되어야 한다.
* 핵심은 **`타입 별칭 = 타입 재사용`, `인덱스 시그니처 = 반복되는 객체 프로퍼티 규칙 표현`**이다.
