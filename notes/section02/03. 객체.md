# Section 2 - 3. 객체

**1. 객체 타입 정의 방법**

TypeScript에서 객체 타입은 크게 두 방식으로 표현할 수 있다.

```text
object 타입
객체 리터럴 타입
```

실무에서는 보통 **객체의 구조를 정확히 표현할 수 있는 객체 리터럴 타입**을 사용한다.

---

**2. object 타입의 한계**

```ts
const user: object = {
  id: 1,
  name: "이정환",
};
```

`object` 타입은 **값이 객체라는 사실만 표현**한다.

따라서 객체 안에 어떤 프로퍼티가 있는지는 알 수 없다.

```ts
user.id;
```

이처럼 `id` 프로퍼티에 바로 접근할 수 없다.

---

**3. 객체 리터럴 타입**

객체가 가진 프로퍼티와 각 타입을 직접 작성한다.

```ts
const user: {
  id: number;
  name: string;
} = {
  id: 1,
  name: "이정환",
};
```

이제 TypeScript는 객체의 구조를 알고 있다.

```text
user
├─ id: number
└─ name: string
```

따라서 정상적으로 접근할 수 있다.

```ts
user.id;
user.name;
```

---

**4. 구조적 타입 시스템**

TypeScript는 객체의 이름보다 **객체가 어떤 프로퍼티 구조를 가지고 있는지**를 기준으로 타입을 판단한다.

```ts
const dog: {
  name: string;
  color: string;
} = {
  name: "돌돌이",
  color: "brown",
};
```

중요한 것은 `dog`라는 이름이 아니라 다음 구조이다.

```text
{
  name: string;
  color: string;
}
```

이처럼 구조를 기준으로 타입을 판단하는 방식을 **구조적 타입 시스템**이라고 한다.

---

**5. 선택적 프로퍼티**

프로퍼티가 없어도 되는 경우 `?`를 사용한다.

```ts
let user: {
  id?: number;
  name: string;
} = {
  id: 1,
  name: "이정환",
};
```

`id`는 생략할 수 있다.

```ts
user = {
  name: "홍길동",
};
```

```text
id: number
→ 반드시 필요

id?: number
→ 있어도 되고 없어도 됨
```

단, `id`가 존재한다면 반드시 `number`여야 한다.

---

**6. readonly 프로퍼티**

값을 수정하지 못하게 하려면 `readonly`를 사용한다.

```ts
const config: {
  readonly apiKey: string;
} = {
  apiKey: "MY API KEY",
};
```

읽는 것은 가능하다.

```ts
console.log(config.apiKey);
```

하지만 수정은 불가능하다.

```ts
config.apiKey = "hacked";
```

`readonly`는 의도하지 않은 프로퍼티 변경을 막는 데 사용할 수 있다.

---

**7. 핵심 문법**

```text
object
→ 객체라는 사실만 표현

{
  id: number;
  name: string;
}
→ 객체의 구조를 직접 표현

id?: number
→ 선택적 프로퍼티

readonly id: number
→ 읽기 전용 프로퍼티
```

---

**8. 핵심 정리**

* `object` 타입은 객체의 내부 구조를 표현하지 못한다.
* 객체 타입은 보통 객체 리터럴 타입으로 정의한다.
* TypeScript는 객체의 **구조**를 기준으로 타입을 판단한다.
* 이를 **구조적 타입 시스템**이라고 한다.
* `?`를 붙이면 선택적 프로퍼티가 된다.
* 선택적 프로퍼티는 생략할 수 있지만, 존재한다면 지정된 타입을 따라야 한다.
* `readonly`를 붙이면 해당 프로퍼티의 값을 수정할 수 없다.
* 핵심은 **객체의 이름이 아니라 프로퍼티 구조를 타입으로 표현하는 것**이다.
