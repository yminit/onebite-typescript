# Section 2 - 6. any와 unknown

**1. any 타입**

`any`는 **타입 검사를 사실상 우회하는 타입**이다.

```ts
let value: any = 10;

value = "hello";
value = true;
value = {};
```

어떤 타입의 값도 저장할 수 있다.

또한 다른 타입의 변수에도 자유롭게 할당할 수 있다.

```ts
let value: any = "hello";

let num: number = value;
let str: string = value;
let bool: boolean = value;
```

---

**2. any의 문제점**

`any`는 타입 검사를 거의 하지 않기 때문에 잘못된 코드도 허용한다.

```ts
let value: any = 10;

value.toUpperCase();
```

TypeScript에서는 오류를 표시하지 않을 수 있지만, 실제 실행하면 숫자에는 `toUpperCase()`가 없기 때문에 런타임 오류가 발생한다.

```text
any 사용
→ 타입 검사 우회
→ 잘못된 코드도 통과 가능
→ 런타임 오류 위험 증가
```

따라서 `any`를 많이 사용하면 TypeScript를 사용하는 장점이 줄어든다.

---

**3. unknown 타입**

`unknown`도 어떤 타입의 값이든 저장할 수 있다.

```ts
let value: unknown;

value = "hello";
value = 10;
value = true;
value = {};
value = () => {};
```

하지만 `any`와 달리 **값을 바로 사용할 수 없다.**

---

**4. unknown은 바로 사용할 수 없다**

다른 타입의 변수에 바로 할당할 수 없다.

```ts
let value: unknown = 10;

let num: number = value;
```

메서드도 바로 호출할 수 없다.

```ts
let value: unknown = "hello";

value.toUpperCase();
```

연산도 바로 할 수 없다.

```ts
let value: unknown = 10;

value * 2;
```

즉,

```text
unknown
→ 값 저장은 가능
→ 사용하려면 타입 확인 필요
```

이다.

---

**5. 타입을 확인한 뒤 사용하기**

`unknown` 값을 사용하려면 먼저 실제 타입을 확인해야 한다.

```ts
let value: unknown = 10;

if (typeof value === "number") {
  console.log(value * 2);
}
```

조건문 안에서는 TypeScript가 `value`를 `number`로 판단한다.

```text
unknown
↓ typeof 검사
number
```

이처럼 타입을 더 구체적으로 만드는 것을 **타입 좁히기(Type Narrowing)**라고 한다.

---

**6. any와 unknown 비교**

```text
any
→ 모든 값 저장 가능
→ 바로 사용 가능
→ 다른 타입에 바로 할당 가능
→ 타입 안전성 낮음

unknown
→ 모든 값 저장 가능
→ 바로 사용 불가
→ 타입 확인 후 사용
→ any보다 안전함
```

---

**7. 언제 무엇을 사용할까?**

값의 타입을 정확히 알 수 없는 상황이라면 가능하면 `any`보다 `unknown`을 사용하는 것이 좋다.

```text
any
→ "타입 검사를 하지 않겠다"

unknown
→ "아직 타입을 모르니 확인한 뒤 사용하겠다"
```

실무에서는 두 번째 방식이 훨씬 안전하다.

---

**8. 핵심 코드**

```ts
let anyValue: any = 10;

anyValue = "hello";
anyValue = true;

let num: number = anyValue;

let unknownValue: unknown = 10;

if (typeof unknownValue === "number") {
  console.log(unknownValue * 2);
}
```

---

**9. 핵심 정리**

* `any`는 타입 검사를 거의 받지 않는다.
* `any`에는 어떤 타입의 값이든 저장할 수 있다.
* `any` 값은 다른 타입에 자유롭게 할당할 수 있다.
* `any`를 사용하면 런타임 오류 위험이 커질 수 있다.
* `unknown`도 모든 타입의 값을 저장할 수 있다.
* 하지만 `unknown` 값은 바로 사용할 수 없다.
* `unknown`을 사용하려면 먼저 타입을 확인해야 한다.
* 타입 확인을 통해 타입을 구체화하는 것을 **타입 좁히기**라고 한다.
* 값의 타입을 알 수 없다면 **`any`보다 `unknown`을 우선하는 것이 안전하다.**
