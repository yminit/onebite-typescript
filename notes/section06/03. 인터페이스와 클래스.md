# Section 6 - 3. 인터페이스와 클래스

**1. 인터페이스는 클래스의 설계도가 될 수 있다**

인터페이스를 사용하면 클래스가 반드시 가져야 할 구조를 미리 정의할 수 있다.

```ts
interface CharacterInterface {
  name: string;
  moveSpeed: number;
  move(): void;
}
```

이 인터페이스는 다음 구조를 요구한다.

```text
name: string
moveSpeed: number
move(): void
```

---

**2. implements**

클래스가 특정 인터페이스의 구조를 따르도록 만들려면 `implements`를 사용한다.

```ts
class Character implements CharacterInterface {}
```

기본 형태:

```ts
class 클래스이름 implements 인터페이스이름 {
  // 구현
}
```

`implements`는 **이 클래스가 해당 인터페이스의 구조를 만족하는지 TypeScript가 검사하게 만드는 것**이다.

---

**3. 인터페이스 구현하기**

인터페이스에 정의된 필드와 메서드를 모두 구현해야 한다.

```ts
interface CharacterInterface {
  name: string;
  moveSpeed: number;
  move(): void;
}

class Character implements CharacterInterface {
  constructor(
    public name: string,
    public moveSpeed: number
  ) {}

  move(): void {
    console.log(`${this.moveSpeed} 속도로 이동!`);
  }
}
```

`Character`는 다음 조건을 모두 만족한다.

```text
name
moveSpeed
move()
```

---

**4. 구현하지 않은 멤버가 있으면 오류**

인터페이스에 정의된 멤버가 빠지면 오류가 발생한다.

```ts
interface CharacterInterface {
  name: string;
  moveSpeed: number;
  move(): void;
}

class Character implements CharacterInterface {
  constructor(
    public name: string,
    public moveSpeed: number
  ) {}

  // move()가 없음
}
```

`CharacterInterface`가 요구하는 `move()`를 구현하지 않았기 때문이다.

---

**5. 생성자 매개변수로 필드 구현하기**

생성자 매개변수에 접근 제어자를 사용하면 필드 선언과 초기화를 동시에 처리할 수 있다.

```ts
class Character implements CharacterInterface {
  constructor(
    public name: string,
    public moveSpeed: number
  ) {}

  move(): void {
    console.log(`${this.moveSpeed} 속도로 이동!`);
  }
}
```

다음 필드가 자동으로 생성된다.

```text
name: string
moveSpeed: number
```

---

**6. 인터페이스 멤버와 접근 제어자**

인터페이스에 정의된 멤버는 외부에서 접근 가능한 구조로 취급된다.

따라서 다음처럼 `private`으로 구현하면 인터페이스를 만족하지 못한다.

```ts
class Character implements CharacterInterface {
  constructor(
    private name: string,
    private moveSpeed: number
  ) {}

  move(): void {
    console.log(`${this.moveSpeed} 속도로 이동!`);
  }
}
```

`name`과 `moveSpeed`가 클래스 외부에서 접근할 수 없기 때문이다.

따라서 인터페이스의 멤버는 보통 `public`으로 구현한다.

```ts
constructor(
  public name: string,
  public moveSpeed: number
) {}
```

---

**7. 인터페이스에 없는 멤버도 추가할 수 있다**

`implements`는 인터페이스에 정의된 것만 가져야 한다는 뜻이 아니다.

필수 구조를 모두 만족한다면 클래스에 추가 멤버가 있어도 된다.

```ts
class Character implements CharacterInterface {
  constructor(
    public name: string,
    public moveSpeed: number,
    private extra: string
  ) {}

  move(): void {
    console.log(`${this.moveSpeed} 속도로 이동!`);
  }
}
```

`extra`는 `CharacterInterface`에는 없지만 문제없다.

```text
인터페이스가 요구하는 구조
→ 반드시 구현

추가 필드 / 메서드
→ 자유롭게 추가 가능
```

---

**8. extends와 implements 차이**

앞에서 배운 클래스 상속과 구분해야 한다.

```text
extends
→ 기존 클래스의 구현을 상속

implements
→ 인터페이스의 구조를 만족하는지 검사
```

예:

```ts
class Dog extends Animal {}
```

`Animal`의 실제 필드와 메서드를 물려받는다.

반면:

```ts
class Character implements CharacterInterface {}
```

인터페이스의 구현을 물려받는 것이 아니라 **요구된 구조를 직접 구현해야 한다.**

---

**9. 전체 코드**

```ts
interface CharacterInterface {
  name: string;
  moveSpeed: number;
  move(): void;
}

class Character implements CharacterInterface {
  constructor(
    public name: string,
    public moveSpeed: number,
    private extra: string
  ) {}

  move(): void {
    console.log(`${this.moveSpeed} 속도로 이동!`);
  }
}

const character = new Character(
  "전사",
  10,
  "추가 정보"
);

character.move();
```

---

**10. 핵심 정리**

* 인터페이스는 클래스가 가져야 할 구조를 정의할 수 있다.
* 클래스에서 인터페이스를 구현할 때 `implements`를 사용한다.
* 인터페이스에 정의된 필드와 메서드를 모두 구현해야 한다.
* 하나라도 빠지면 TypeScript 오류가 발생한다.
* 생성자 매개변수의 `public`을 이용해 인터페이스의 필드를 간단하게 구현할 수 있다.
* 인터페이스가 요구하는 멤버를 `private`으로 구현하면 인터페이스 구조를 만족하지 못한다.
* 인터페이스에 없는 추가 필드나 메서드를 클래스에 만드는 것은 가능하다.
* `extends`는 구현을 물려받는 **상속**, `implements`는 구조를 만족하는지 검사하는 **계약**에 가깝다.
* 핵심은 **`interface = 클래스가 지켜야 할 구조`, `implements = 그 구조를 제대로 구현했는지 검사`**이다.
