# Section 9 - 0. 조건부 타입

조건부 타입은 `extends`와 삼항 연산자를 이용해 **조건에 따라 다른 타입을 선택하는 기능**이다.

**1. 조건부 타입 기본 문법**

```ts
A extends B ? C : D
```

의미:

```text
A가 B에 할당 가능한 타입이면
→ C

그렇지 않으면
→ D
```

예:

```ts
type A =
  number extends string
    ? number
    : string;
```

`number`는 `string`에 할당할 수 없으므로 결과는 `string`이다.

```ts
type A = string;
```

---

**2. 객체 타입에도 사용할 수 있다**

```ts
type ObjA = {
  a: number;
};

type ObjB = {
  a: number;
  b: number;
};
```

`ObjB`는 `ObjA`가 요구하는 구조를 모두 가지고 있다.

```ts
type B =
  ObjB extends ObjA
    ? number
    : string;
```

결과:

```ts
type B = number;
```

즉, 조건부 타입의 `extends`는 **두 타입이 호환되는지 검사하는 조건**으로 사용된다.

---

**3. 제네릭과 함께 사용하기**

조건부 타입은 제네릭과 결합했을 때 특히 유용하다. 타입 변수에 어떤 타입이 들어오는지에 따라 결과 타입을 바꿀 수 있다.

```ts
type StringNumberSwitch<T> =
  T extends number
    ? string
    : number;
```

숫자를 전달하면:

```ts
type A =
  StringNumberSwitch<number>;
```

```text
number extends number
→ 참
→ string
```

문자열을 전달하면:

```ts
type B =
  StringNumberSwitch<string>;
```

```text
string extends number
→ 거짓
→ number
```

즉:

```text
StringNumberSwitch<number>
→ string

StringNumberSwitch<string>
→ number
```

---

**4. 함수에 조건부 타입이 필요한 상황**

다음 함수가 문자열 또는 `undefined`, `null`을 받을 수 있다고 하자.

```ts
function removeSpaces(
  text: string | undefined | null
) {
  if (typeof text === "string") {
    return text.replaceAll(" ", "");
  }

  return undefined;
}
```

반환 타입은 다음처럼 추론된다.

```ts
string | undefined
```

따라서 문자열을 전달해도:

```ts
const result = removeSpaces(
  "hi im winterlood"
);
```

`result` 타입은 여전히:

```ts
string | undefined
```

이다.

하지만 실제 의도는 다음과 같다.

```text
string 전달
→ string 반환

undefined 전달
→ undefined 반환
```

---

**5. 제네릭 조건부 타입으로 반환 타입 연결하기**

```ts
function removeSpaces<T>(
  text: T
): T extends string
  ? string
  : undefined {
  // 구현
}
```

반환 타입:

```ts
T extends string
  ? string
  : undefined
```

따라서 문자열을 전달하면:

```ts
const result = removeSpaces(
  "hi im winterlood"
);
```

```text
T → string

string extends string
→ 참

result → string
```

`undefined`를 전달하면:

```ts
const result2 =
  removeSpaces(undefined);
```

```text
T → undefined

undefined extends string
→ 거짓

result2 → undefined
```

즉, **입력 타입과 반환 타입의 관계를 조건부 타입으로 표현할 수 있다.**

---

**6. 함수 구현부에서 생기는 문제**

다음처럼 조건부 타입을 직접 반환 타입으로 사용하면:

```ts
function removeSpaces<T>(
  text: T
): T extends string
  ? string
  : undefined {
  if (typeof text === "string") {
    return text.replaceAll(" ", "");
  }

  return undefined;
}
```

구현부의 `return`에서 타입 오류가 발생할 수 있다.

이유는 함수 구현 시점에는 `T`가 정확히 어떤 타입인지 확정되지 않았기 때문이다.

```text
호출 시점
→ T가 결정됨
→ 조건부 타입 계산 가능

함수 구현 내부
→ T가 아직 구체적으로 결정되지 않음
→ 반환 타입 판단이 어려움
```

---

**7. any 단언은 피하는 편이 좋다**

오류를 없애기 위해 다음처럼 작성할 수도 있다.

```ts
return text.replaceAll(" ", "") as any;
```

하지만 `any`를 사용하면 잘못된 값도 통과할 수 있다.

```ts
return 0 as any;
```

호출부에서는 `string`을 반환한다고 생각하지만 실제 구현은 `number`를 반환할 수도 있으므로 타입 안전성이 떨어진다.

---

**8. 함수 오버로딩 활용하기**

이런 경우에는 오버로드 시그니처와 구현 시그니처를 분리할 수 있다.

```ts
function removeSpaces<T>(
  text: T
): T extends string
  ? string
  : undefined;

function removeSpaces(text: any) {
  if (typeof text === "string") {
    return text.replaceAll(" ", "");
  }

  return undefined;
}
```

역할을 나누면:

```text
오버로드 시그니처
→ 호출할 때 보이는 타입 관계 정의

구현 시그니처
→ 실제 함수 동작 구현
```

호출 결과:

```ts
const result = removeSpaces(
  "hi im winterlood"
);
// string

const result2 =
  removeSpaces(undefined);
// undefined
```

이렇게 하면 호출부에서는 조건부 타입에 따라 더 정확한 결과 타입을 얻을 수 있다.

---

**9. 전체 코드**

```ts
type A =
  number extends string
    ? number
    : string;

type ObjA = {
  a: number;
};

type ObjB = {
  a: number;
  b: number;
};

type B =
  ObjB extends ObjA
    ? number
    : string;

type StringNumberSwitch<T> =
  T extends number
    ? string
    : number;

const varA:
  StringNumberSwitch<number> = "hello";

const varB:
  StringNumberSwitch<string> = 10;

function removeSpaces<T>(
  text: T
): T extends string
  ? string
  : undefined;

function removeSpaces(text: any) {
  if (typeof text === "string") {
    return text.replaceAll(" ", "");
  }

  return undefined;
}

const result = removeSpaces(
  "hi im winterlood"
);

const result2 =
  removeSpaces(undefined);
```

---

**10. 핵심 정리**

* 조건부 타입은 `A extends B ? C : D` 형태로 작성한다.
* `A`가 `B`에 할당 가능한 타입이면 `C`, 아니면 `D`가 된다.
* 기본 타입뿐 아니라 객체 타입에도 사용할 수 있다.
* 제네릭과 결합하면 전달된 타입에 따라 결과 타입을 다르게 만들 수 있다.
* 함수의 **입력 타입과 반환 타입 사이의 관계**를 표현할 때 활용할 수 있다.
* 제네릭 조건부 타입은 함수 구현부에서 바로 처리하기 어려운 경우가 있다.
* `as any`로 강제로 해결하면 타입 안전성이 떨어질 수 있다.
* 이런 경우 오버로드 시그니처로 호출 타입을 정의하고 구현부를 분리하는 방법을 사용할 수 있다.
* 핵심은 **`조건부 타입 = 타입 수준에서 사용하는 if문`**이라고 이해하면 된다.
