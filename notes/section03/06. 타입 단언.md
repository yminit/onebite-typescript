# Section 3 - 6. 타입 단언

**1. 타입 단언이란?**

타입 단언은 **개발자가 TypeScript에게 특정 값을 다른 타입으로 취급하라고 알려주는 문법**이다.

기본 형태:

```ts
값 as 타입
```

예:

```ts
type Person = {
  name: string;
  age: number;
};

const person = {} as Person;
```

TypeScript는 `person`을 `Person` 타입으로 취급한다.

중요한 점은 **실제 값이 바뀌는 것이 아니라 타입 검사 결과만 바뀐다는 것**이다.

---

**2. 타입 단언을 사용하는 이유**

타입 단언은 TypeScript가 현재 코드만으로는 충분히 알 수 없지만, 개발자는 값의 타입을 확실히 알고 있을 때 사용할 수 있다.

예를 들어 빈 객체를 먼저 만든 뒤 나중에 프로퍼티를 채우는 경우이다.

```ts
type Person = {
  name: string;
  age: number;
};

const person = {} as Person;

person.name = "홍길동";
person.age = 30;
```

다만 이런 방식은 완성되지 않은 객체를 `Person`이라고 강제로 믿게 만드는 것이므로 신중하게 사용해야 한다.

---

**3. 타입 단언과 초과 프로퍼티 검사**

객체 리터럴을 직접 할당하면 초과 프로퍼티 검사가 발생할 수 있다.

```ts
type Dog = {
  name: string;
  color: string;
};

const dog: Dog = {
  name: "돌돌이",
  color: "brown",
  breed: "진도",
};
```

`breed`가 `Dog`에 없기 때문에 오류가 발생한다.

타입 단언을 사용하면 이 검사를 우회할 수 있다.

```ts
const dog = {
  name: "돌돌이",
  color: "brown",
  breed: "진도",
} as Dog;
```

하지만 단순히 오류를 없애기 위해 단언을 사용하는 습관은 피하는 것이 좋다.

---

**4. 타입 단언이 가능한 조건**

다음 단언이 있다고 하자.

```ts
A as B
```

일반적으로 `A`와 `B` 중 한쪽이 다른 쪽에 할당 가능한 관계여야 한다.

```text
A → B 가능
또는
B → A 가능
```

즉, 두 타입이 충분히 관련되어 있어야 한다.

예:

```ts
const num = 10 as number;
```

반면 서로 전혀 관련 없는 타입은 직접 단언할 수 없다.

```ts
const value = 10 as string;
```

`number`와 `string`은 서로 충분히 관련되지 않았기 때문에 오류가 발생한다.

---

**5. 다중 단언**

관련 없는 타입으로 강제로 바꾸고 싶다면 중간에 `unknown`을 사용할 수 있다.

```ts
const value = 10 as unknown as string;
```

흐름:

```text
number
→ unknown
→ string
```

이를 **다중 단언**이라고 한다.

하지만 실제 숫자 `10`이 문자열로 변하는 것은 아니다.

```text
실제 값
→ 여전히 숫자 10

TypeScript가 보는 타입
→ string
```

따라서 다중 단언은 런타임 오류를 만들 수 있으므로 특별한 이유가 없다면 피하는 것이 좋다.

---

**6. const 단언**

`as const`를 사용하면 값을 **가능한 한 좁고 읽기 전용인 타입**으로 추론하게 할 수 있다.

```ts
const user = {
  name: "홍길동",
  role: "ADMIN",
} as const;
```

일반적으로는 다음처럼 추론될 수 있다.

```text
name → string
role → string
```

`as const`를 사용하면 리터럴 정보를 유지한다.

```text
name → "홍길동"
role → "ADMIN"
```

객체 프로퍼티도 `readonly`로 취급된다.

```ts
user.role = "USER";
```

수정할 수 없다.

---

**7. const 선언과 as const는 다르다**

```ts
const user = {
  role: "ADMIN",
};
```

변수 `user` 자체를 다른 객체로 재할당할 수는 없지만 프로퍼티는 수정할 수 있다.

```ts
user.role = "USER";
```

반면:

```ts
const user = {
  role: "ADMIN",
} as const;
```

프로퍼티까지 읽기 전용으로 추론된다.

```text
const
→ 변수 재할당 방지

as const
→ 타입을 리터럴 중심으로 좁힘
→ 객체/배열 요소를 readonly로 추론
```

---

**8. Non-null 단언**

값 뒤에 `!`를 붙이면 TypeScript에게 **이 값은 `null`이나 `undefined`가 아니라고 알려줄 수 있다.**

```ts
value!
```

예:

```ts
let value: string | undefined;

const length = value!.length;
```

TypeScript는 `value!`를 `string`처럼 취급한다.

```text
string | undefined
↓ !
string
```

---

**9. Non-null 단언도 실제 검사를 하지 않는다**

`!`는 런타임에 값을 검사하지 않는다.

```ts
let value: string | undefined;

console.log(value!.length);
```

실제로 `value`가 `undefined`라면 런타임 오류가 발생할 수 있다.

따라서 가능하면 먼저 값을 확인하는 것이 안전하다.

```ts
if (value !== undefined) {
  console.log(value.length);
}
```

---

**10. 타입 단언 종류**

```text
값 as 타입
→ 일반 타입 단언

값 as unknown as 타입
→ 다중 단언

값 as const
→ 리터럴 타입 유지 + readonly

값!
→ null / undefined가 아니라고 단언
```

---

**11. 타입 단언 사용 기준**

타입 단언은 **TypeScript보다 개발자가 더 많은 정보를 확실히 알고 있을 때** 사용하는 도구이다.

```text
좋은 사용
→ 실제 타입을 확실히 알고 있음
→ TypeScript만 그 사실을 알지 못함

주의할 사용
→ 단순히 타입 오류를 없애기 위해 사용
→ 실제 값과 단언한 타입이 다를 수 있음
```

타입 단언은 타입 안전성을 강화하는 기능이 아니라, 경우에 따라 **TypeScript의 검사를 우회하는 기능**이 될 수 있다.

---

**12. 핵심 정리**

* 타입 단언은 `값 as 타입` 형태로 작성한다.
* 실제 값을 변환하지 않고 TypeScript가 판단하는 타입만 바꾼다.
* 빈 객체 초기화나 TypeScript가 타입을 정확히 알지 못하는 상황에서 사용할 수 있다.
* 객체 리터럴의 초과 프로퍼티 검사를 우회할 수도 있다.
* 서로 관련 없는 타입으로 직접 단언할 수는 없다.
* `as unknown as 타입`을 사용하면 강제로 다중 단언할 수 있지만 위험하다.
* `as const`는 리터럴 정보를 유지하고 객체·배열을 더 읽기 전용으로 추론한다.
* `값!`은 `null`, `undefined`가 아니라고 단언한다.
* Non-null 단언 역시 실제 런타임 검사를 하지 않는다.
* 핵심은 **타입 단언은 값을 바꾸는 기능이 아니라 TypeScript의 판단만 바꾸는 기능**이라는 것이다.
