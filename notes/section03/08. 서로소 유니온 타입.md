# Section 3 - 8. 서로소 유니온 타입

**1. 서로소 유니온 타입이란?**

서로소 유니온 타입은 **각 타입을 명확하게 구분할 수 있는 공통 식별 프로퍼티를 가진 유니온 타입**이다.

예:

```ts
type Admin = {
  tag: "ADMIN";
  name: string;
  kickCount: number;
};

type Member = {
  tag: "MEMBER";
  name: string;
  point: number;
};

type Guest = {
  tag: "GUEST";
  name: string;
  visitCount: number;
};

type User = Admin | Member | Guest;
```

각 타입은 같은 `tag` 프로퍼티를 가지지만 값은 서로 다르다.

```text
Admin  → tag: "ADMIN"
Member → tag: "MEMBER"
Guest  → tag: "GUEST"
```

이 `tag`를 이용하면 각 타입을 명확하게 구분할 수 있다.

---

**2. 일반적인 객체 Union의 타입 좁히기**

식별용 프로퍼티가 없어도 특정 프로퍼티 존재 여부를 이용해 좁힐 수 있다.

```ts
type Admin = {
  name: string;
  kickCount: number;
};

type Member = {
  name: string;
  point: number;
};

type Guest = {
  name: string;
  visitCount: number;
};

type User = Admin | Member | Guest;
```

```ts
function login(user: User) {
  if ("kickCount" in user) {
    // user: Admin
  } else if ("point" in user) {
    // user: Member
  } else {
    // user: Guest
  }
}
```

동작은 하지만 조건만 보고 어떤 타입인지 바로 파악하기 어렵다는 단점이 있다.

---

**3. 식별 프로퍼티를 추가한다**

각 타입에 동일한 이름의 프로퍼티를 추가하고 서로 다른 리터럴 타입을 지정한다.

```ts
type Admin = {
  tag: "ADMIN";
  name: string;
  kickCount: number;
};

type Member = {
  tag: "MEMBER";
  name: string;
  point: number;
};

type Guest = {
  tag: "GUEST";
  name: string;
  visitCount: number;
};
```

```text
공통 프로퍼티
→ tag

서로 다른 값
→ "ADMIN"
→ "MEMBER"
→ "GUEST"
```

이런 프로퍼티를 기준으로 타입을 구분할 수 있다.

---

**4. tag로 타입 좁히기**

```ts
function login(user: User) {
  if (user.tag === "ADMIN") {
    console.log(
      `${user.name}님 현재까지 ${user.kickCount}명 강퇴했습니다.`
    );
  } else if (user.tag === "MEMBER") {
    console.log(
      `${user.name}님 현재까지 ${user.point} 모았습니다.`
    );
  } else {
    console.log(
      `${user.name}님 현재까지 ${user.visitCount}번 방문하셨습니다.`
    );
  }
}
```

각 조건문에서 타입이 자동으로 좁혀진다.

```text
user.tag === "ADMIN"
→ Admin

user.tag === "MEMBER"
→ Member

나머지
→ Guest
```

---

**5. switch와 함께 사용하기**

서로소 유니온 타입은 `switch`와 잘 어울린다.

```ts
function login(user: User) {
  switch (user.tag) {
    case "ADMIN":
      console.log(
        `${user.name}님 현재까지 ${user.kickCount}명 강퇴했습니다.`
      );
      break;

    case "MEMBER":
      console.log(
        `${user.name}님 현재까지 ${user.point} 모았습니다.`
      );
      break;

    case "GUEST":
      console.log(
        `${user.name}님 현재까지 ${user.visitCount}번 방문하셨습니다.`
      );
      break;
  }
}
```

각 `case` 내부에서 `user` 타입이 해당 타입으로 좁혀진다.

```text
"ADMIN"  → Admin
"MEMBER" → Member
"GUEST"  → Guest
```

---

**6. 기존 방식과 비교**

프로퍼티 존재 여부를 확인하는 방식:

```ts
if ("kickCount" in user) {
  // Admin
}
```

식별 프로퍼티를 사용하는 방식:

```ts
if (user.tag === "ADMIN") {
  // Admin
}
```

두 번째 방식은 **조건만 봐도 타입의 의미를 바로 알 수 있어 더 명확하다.**

---

**7. 실무에서 자주 쓰는 형태**

식별 프로퍼티의 이름은 반드시 `tag`일 필요는 없다.

다음처럼 사용할 수 있다.

```text
type
kind
status
role
```

예:

```ts
type Success = {
  status: "SUCCESS";
  data: string;
};

type Fail = {
  status: "FAIL";
  message: string;
};

type Result = Success | Fail;
```

```ts
function handleResult(result: Result) {
  if (result.status === "SUCCESS") {
    console.log(result.data);
  } else {
    console.log(result.message);
  }
}
```

이런 구조는 API 상태나 UI 상태를 표현할 때도 유용하다.

---

**8. 핵심 구조**

```text
공통 식별 프로퍼티
+
서로 다른 리터럴 값
↓
각 타입을 명확하게 구분
↓
타입 좁히기 쉬움
```

예:

```text
tag: "ADMIN"
tag: "MEMBER"
tag: "GUEST"
```

---

**9. 핵심 정리**

* 서로소 유니온 타입은 각 타입을 명확하게 구분할 수 있는 유니온 타입이다.
* 공통 프로퍼티에 서로 다른 리터럴 값을 지정해 구분할 수 있다.
* `tag`, `type`, `kind`, `status` 같은 프로퍼티를 사용할 수 있다.
* 식별 프로퍼티를 검사하면 TypeScript가 해당 타입으로 자동으로 좁힌다.
* `"kickCount" in user` 방식보다 `user.tag === "ADMIN"` 방식이 의미를 파악하기 쉽다.
* `switch`문과 함께 사용하면 여러 타입의 분기를 깔끔하게 처리할 수 있다.
* 핵심은 **`공통 식별 프로퍼티 + 서로 다른 리터럴 값`**이다.
