# Section 5 - 2. 인터페이스 선언 합치기

**1. 선언 합침이란?**

인터페이스는 같은 이름으로 여러 번 선언할 수 있다.

```ts
interface Person {
  name: string;
}

interface Person {
  age: number;
}
```

TypeScript는 두 선언을 하나로 합친다.

```ts
interface Person {
  name: string;
  age: number;
}
```

이 동작을 **선언 합침(Declaration Merging)**이라고 한다.

---

**2. 타입 별칭과의 차이**

타입 별칭은 같은 이름으로 다시 선언할 수 없다.

```ts
type Person = {
  name: string;
};

type Person = {
  age: number;
};
```

오류가 발생한다.

반면 인터페이스는 가능하다.

```ts
interface Person {
  name: string;
}

interface Person {
  age: number;
}
```

```text
type
→ 같은 이름 재선언 불가

interface
→ 같은 이름 재선언 가능
→ 선언 내용이 하나로 합쳐짐
```

---

**3. 합쳐진 인터페이스 사용하기**

선언이 합쳐지면 모든 프로퍼티를 만족해야 한다.

```ts
interface Person {
  name: string;
}

interface Person {
  age: number;
}

const person: Person = {
  name: "이정환",
  age: 27,
};
```

최종 `Person`의 구조는 다음과 같다.

```text
Person
├─ name: string
└─ age: number
```

---

**4. 같은 프로퍼티가 있으면 주의**

같은 프로퍼티를 다시 선언할 수도 있지만 타입이 호환되어야 한다.

```ts
interface Person {
  name: string;
}

interface Person {
  name: string;
  age: number;
}
```

`name`의 타입이 동일하므로 문제없다.

하지만 다음은 오류가 발생한다.

```ts
interface Person {
  name: string;
}

interface Person {
  name: number;
}
```

```text
name: string
     ↕
name: number

→ 타입 충돌
```

선언 합침에서는 같은 프로퍼티의 타입을 서로 다르게 정의할 수 없다.

---

**5. 선언 합침의 흐름**

```text
첫 번째 Person
{
  name: string
}

+

두 번째 Person
{
  age: number
}

↓

하나의 Person
{
  name: string
  age: number
}
```

즉, 이름이 같은 인터페이스를 별개의 타입으로 만드는 것이 아니라 하나의 타입 정의를 나누어 작성한 것으로 처리한다.

---

**6. 선언 합침을 사용하는 이유**

선언 합침은 기존 인터페이스에 새로운 구조를 추가할 때 활용할 수 있다.

```ts
interface User {
  id: number;
}

interface User {
  name: string;
}
```

결과:

```ts
interface User {
  id: number;
  name: string;
}
```

특히 기존 인터페이스를 확장해야 하는 상황에서 활용될 수 있다는 점이 인터페이스의 중요한 특징이다.

---

**7. 핵심 코드**

```ts
interface Person {
  name: string;
}

interface Person {
  age: number;
}

const person: Person = {
  name: "이정환",
  age: 27,
};
```

충돌하는 경우:

```ts
interface Person {
  name: string;
}

interface Person {
  name: number;
}
```

위 코드는 같은 `name` 프로퍼티의 타입이 다르므로 오류가 발생한다.

---

**8. 핵심 정리**

* 타입 별칭은 같은 스코프에서 같은 이름으로 중복 선언할 수 없다.
* 인터페이스는 같은 이름으로 여러 번 선언할 수 있다.
* 같은 이름의 인터페이스들은 하나의 타입으로 합쳐진다.
* 이를 **선언 합침(Declaration Merging)**이라고 한다.
* 합쳐진 인터페이스는 각 선언의 프로퍼티를 모두 가진다.
* 같은 이름의 프로퍼티를 반복 선언한다면 타입이 서로 충돌하지 않아야 한다.
* 핵심은 **`interface는 같은 이름으로 다시 선언하면 새로운 타입이 생기는 것이 아니라 기존 선언에 내용이 합쳐진다`**는 것이다.
