# Section 5 - 0. 인터페이스

**1. 인터페이스란?**

인터페이스는 **객체 타입에 이름을 붙이는 문법**이다.

```ts
interface Person {
  name: string;
  age: number;
}
```

기본 형태:

```ts
interface 인터페이스이름 {
  프로퍼티이름: 타입;
}
```

정의한 인터페이스는 변수의 타입으로 사용할 수 있다.

```ts
const person: Person = {
  name: "이정환",
  age: 27,
};
```

---

**2. 타입 별칭과 인터페이스**

객체 타입은 타입 별칭과 인터페이스 모두로 정의할 수 있다.

타입 별칭:

```ts
type Person = {
  name: string;
  age: number;
};
```

인터페이스:

```ts
interface Person {
  name: string;
  age: number;
}
```

기본적인 객체 타입 표현은 비슷하지만, 이후 배우게 될 **확장과 선언 병합** 같은 부분에서 차이가 있다.

---

**3. 선택적 프로퍼티**

프로퍼티 뒤에 `?`를 붙이면 생략할 수 있다.

```ts
interface Person {
  name: string;
  age?: number;
}
```

```ts
const person: Person = {
  name: "이정환",
};
```

`age`는 있어도 되고 없어도 된다.

---

**4. readonly 프로퍼티**

`readonly`를 붙이면 객체 생성 이후 해당 프로퍼티를 수정할 수 없다.

```ts
interface Person {
  readonly name: string;
  age?: number;
}
```

```ts
const person: Person = {
  name: "이정환",
  age: 27,
};

person.name = "홍길동";
```

마지막 코드는 오류가 발생한다.

---

**5. 메서드 타입 정의**

인터페이스 안에는 메서드 타입도 정의할 수 있다.

프로퍼티에 함수 타입을 지정하는 방식:

```ts
interface Person {
  name: string;
  sayHi: () => void;
}
```

메서드 시그니처 방식:

```ts
interface Person {
  name: string;
  sayHi(): void;
}
```

둘 다 `sayHi`라는 함수를 가진 객체를 표현한다.

---

**6. 메서드 구현**

```ts
interface Person {
  name: string;
  sayHi(): void;
}

const person: Person = {
  name: "이정환",

  sayHi() {
    console.log("Hi");
  },
};
```

객체의 메서드가 인터페이스에 정의된 매개변수와 반환 타입을 만족해야 한다.

---

**7. 메서드 오버로딩**

메서드 시그니처 방식은 같은 이름의 호출 형태를 여러 개 정의할 수 있다.

```ts
interface Person {
  sayHi(): void;
  sayHi(a: number): void;
  sayHi(a: number, b: number): void;
}
```

구현:

```ts
const person: Person = {
  sayHi(a?: number, b?: number) {
    console.log("Hi");
  },
};
```

즉:

```text
sayHi()
sayHi(number)
sayHi(number, number)
```

형태로 호출할 수 있다.

---

**8. 호출 가능한 인터페이스**

인터페이스 자체에 호출 시그니처를 정의할 수도 있다.

```ts
interface Func {
  (): void;
}
```

이 타입의 값은 함수처럼 호출할 수 있어야 한다.

```text
Func
→ () => void 형태로 호출 가능
```

---

**9. 함수 + 프로퍼티를 가진 타입**

호출 시그니처와 일반 프로퍼티를 함께 작성할 수도 있다.

```ts
interface Func {
  (): void;
  property: string;
}
```

이 타입은 다음 두 조건을 모두 만족한다.

```text
함수처럼 호출 가능
+
property 프로퍼티 보유
```

즉, JavaScript 함수가 객체이기도 하다는 특징을 타입으로 표현한 것이다.

---

**10. 인터페이스와 Union / Intersection**

인터페이스 문법 자체로 다음처럼 Union 타입을 정의할 수는 없다.

```ts
interface Value = number | string;
```

Intersection도 같은 방식으로 정의할 수 없다.

```ts
interface Person = Name & Age;
```

이런 타입 조합에는 타입 별칭을 사용한다.

```ts
type Value = number | string;
```

```ts
type Person = Name & Age;
```

---

**11. 인터페이스도 Union과 Intersection의 재료로 사용할 수 있다**

인터페이스로 정의한 타입 자체는 자유롭게 조합할 수 있다.

```ts
interface Dog {
  name: string;
  color: string;
}

interface Cat {
  name: string;
  isScratch: boolean;
}

type Animal = Dog | Cat;
```

Intersection도 가능하다.

```ts
interface Name {
  name: string;
}

interface Age {
  age: number;
}

type Person = Name & Age;
```

---

**12. 타입 주석에서 직접 조합하기**

반드시 타입 별칭을 만들 필요도 없다.

```ts
let animal: Dog | Cat;
```

```ts
let person: Name & Age;
```

인터페이스로 만든 타입도 일반 타입처럼 `|`, `&`의 구성 요소로 사용할 수 있다.

---

**13. 타입 별칭과 인터페이스의 기본 차이**

```text
type
→ 객체뿐 아니라 Union, Intersection, 원시 타입 등
  다양한 타입에 이름을 붙일 수 있음

interface
→ 주로 객체의 구조를 표현하는 데 사용
```

따라서:

```ts
type Id = string | number;
```

는 가능하지만,

```ts
interface Id = string | number;
```

와 같은 형태는 사용할 수 없다.

---

**14. 핵심 코드**

```ts
interface Person {
  readonly name: string;
  age?: number;

  sayHi(): void;
  sayHi(a: number): void;
  sayHi(a: number, b: number): void;
}

const person: Person = {
  name: "이정환",
  age: 27,

  sayHi(a?: number, b?: number) {
    console.log("Hi");
  },
};

interface Func {
  (): void;
  property: string;
}

interface Dog {
  name: string;
  color: string;
}

interface Cat {
  name: string;
  isScratch: boolean;
}

type Animal = Dog | Cat;
```

---

**15. 핵심 정리**

* 인터페이스는 주로 **객체의 구조에 이름을 붙이는 문법**이다.
* `interface 이름 {}` 형태로 작성한다.
* 선택적 프로퍼티는 `?`를 사용한다.
* 읽기 전용 프로퍼티는 `readonly`를 사용한다.
* 인터페이스 안에 메서드 타입도 정의할 수 있다.
* `sayHi(): void` 같은 메서드 시그니처는 오버로딩을 표현할 수 있다.
* 호출 시그니처를 사용하면 함수처럼 호출할 수 있는 타입도 만들 수 있다.
* 호출 시그니처와 프로퍼티를 함께 사용해 함수이면서 객체인 타입도 표현할 수 있다.
* 인터페이스 자체로 Union이나 Intersection을 직접 정의하지는 못한다.
* 하지만 인터페이스로 만든 타입은 `Dog | Cat`, `Name & Age`처럼 자유롭게 조합할 수 있다.
* 핵심은 **`interface = 객체 구조 표현`, `type = 더 넓은 범위의 타입 조합 가능`**으로 이해하면 된다.
