# Section 7 - 2. map, forEach 메서드 타입 정의하기

**1. 이번 시간의 핵심**

제네릭을 이용해 배열 메서드인 `map`과 `forEach`의 타입 구조를 직접 만들어본다.

핵심 차이는 다음과 같다.

```text
map
→ 원본 요소 타입 T
→ 콜백 반환 타입 U
→ 새로운 U[] 반환

forEach
→ 요소 타입 T
→ 콜백 실행
→ 반환값 없음
```

---

**2. map 직접 만들기**

`map`은 배열의 각 요소를 콜백 함수에 전달하고, 콜백의 반환값을 모아 새로운 배열을 만든다.

```ts
function map<T, U>(
  arr: T[],
  callback: (item: T) => U
): U[] {
  const result: U[] = [];

  for (let i = 0; i < arr.length; i++) {
    result.push(callback(arr[i]));
  }

  return result;
}
```

타입 변수의 역할:

```text
T
→ 원본 배열 요소 타입

U
→ 콜백 반환값 타입
→ 새로운 배열 요소 타입
```

---

**3. 왜 T 하나로는 부족할까?**

처음에는 다음처럼 생각할 수 있다.

```ts
function map<T>(
  arr: T[],
  callback: (item: T) => T
): T[] {}
```

이 타입은 입력과 출력의 요소 타입이 같아야 한다.

```text
number[]
→ number[]

string[]
→ string[]
```

하지만 실제 `map`은 타입을 변환할 수도 있다.

```ts
const strings = map([1, 2, 3], (item) => {
  return item.toString();
});
```

원하는 흐름:

```text
number[]
↓
callback
↓
string[]
```

따라서 입력과 출력 타입을 분리해야 한다.

---

**4. T와 U를 분리한다**

```ts
function map<T, U>(
  arr: T[],
  callback: (item: T) => U
): U[] {
  const result: U[] = [];

  for (let i = 0; i < arr.length; i++) {
    result.push(callback(arr[i]));
  }

  return result;
}
```

숫자를 숫자로 변환하면:

```ts
const numbers = map([1, 2, 3], (item) => {
  return item * 2;
});
```

```text
T → number
U → number

반환값 → number[]
```

숫자를 문자열로 변환하면:

```ts
const strings = map([1, 2, 3], (item) => {
  return item.toString();
});
```

```text
T → number
U → string

반환값 → string[]
```

---

**5. map에서 타입 추론이 일어나는 과정**

```ts
map([1, 2, 3], (item) => {
  return item.toString();
});
```

첫 번째 인수로부터:

```text
[1, 2, 3]
→ number[]
→ T = number
```

따라서 콜백의 `item`은 자동으로 `number`가 된다.

```ts
(item) => {
  return item.toString();
}
```

콜백 반환값으로부터:

```text
item.toString()
→ string
→ U = string
```

최종적으로:

```text
map 반환 타입
→ U[]
→ string[]
```

---

**6. forEach 직접 만들기**

`forEach`는 배열의 모든 요소에 콜백을 실행하지만 새로운 배열을 만들지 않는다.

```ts
function forEach<T>(
  arr: T[],
  callback: (item: T) => void
): void {
  for (let i = 0; i < arr.length; i++) {
    callback(arr[i]);
  }
}
```

여기서는 타입 변수 하나만 필요하다.

```text
T
→ 배열 요소 타입
→ 콜백 매개변수 타입
```

---

**7. forEach 타입 추론**

숫자 배열:

```ts
forEach([1, 2, 3], (item) => {
  console.log(item.toFixed());
});
```

```text
T → number
item → number
```

문자열 배열:

```ts
forEach(["a", "b", "c"], (item) => {
  console.log(item.toUpperCase());
});
```

```text
T → string
item → string
```

전달한 배열의 요소 타입을 기준으로 콜백 매개변수 타입이 자동으로 결정된다.

---

**8. map과 forEach의 차이**

`map`:

```ts
function map<T, U>(
  arr: T[],
  callback: (item: T) => U
): U[]
```

```text
T → 입력 타입
U → 출력 타입

입력과 출력 타입이 달라도 됨
```

`forEach`:

```ts
function forEach<T>(
  arr: T[],
  callback: (item: T) => void
): void
```

```text
T → 입력 타입

콜백 결과를 새로운 배열로 만들지 않음
```

---

**9. 중요한 차이: callback의 void**

```ts
callback: (item: T) => void
```

여기서 `void`는 `forEach`가 **콜백의 반환값을 사용하지 않는다**는 의미로 이해하는 것이 좋다.

예를 들어 콜백이 실제로 값을 반환하더라도:

```ts
forEach([1, 2, 3], (item) => {
  return item * 2;
});
```

`forEach`는 그 값을 모아 새로운 배열을 만들지 않는다.

즉, `map`과의 핵심 차이는 콜백 반환값을 **사용하느냐 사용하지 않느냐**이다.

---

**10. 전체 코드**

```ts
function map<T, U>(
  arr: T[],
  callback: (item: T) => U
): U[] {
  const result: U[] = [];

  for (let i = 0; i < arr.length; i++) {
    result.push(callback(arr[i]));
  }

  return result;
}

const numbers = map([1, 2, 3], (item) => {
  return item * 2;
});

const strings = map([1, 2, 3], (item) => {
  return item.toString();
});

function forEach<T>(
  arr: T[],
  callback: (item: T) => void
): void {
  for (let i = 0; i < arr.length; i++) {
    callback(arr[i]);
  }
}

forEach([1, 2, 3], (item) => {
  console.log(item.toFixed());
});

forEach(["a", "b", "c"], (item) => {
  console.log(item.toUpperCase());
});
```

---

**11. 핵심 정리**

* `map`은 배열 요소를 변환해 새로운 배열을 반환한다.
* `map`은 입력과 출력 타입이 다를 수 있으므로 `<T, U>` 두 타입 변수를 사용한다.
* `T`는 원본 배열의 요소 타입이다.
* `U`는 콜백 반환값이자 새로운 배열의 요소 타입이다.
* `map<T, U>(T[], (T) => U): U[]` 구조로 이해하면 된다.
* `forEach`는 각 요소에 콜백을 실행하지만 새로운 배열을 반환하지 않는다.
* `forEach`는 배열 요소 타입 하나만 필요하므로 `<T>`를 사용한다.
* `forEach<T>(T[], (T) => void): void` 구조로 이해하면 된다.
* `void` 콜백은 반환값을 반드시 만들지 말라는 의미라기보다 **반환값을 사용하지 않는다는 의미**에 가깝다.
* 핵심은 **`map = T를 U로 변환`, `forEach = T를 이용해 작업만 수행`**이다.
