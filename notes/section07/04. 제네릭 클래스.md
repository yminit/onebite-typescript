# Section 7 - 4. 제네릭 클래스

**1. 제네릭 클래스란?**

제네릭 클래스는 **타입만 다르고 구조와 동작은 같은 클래스를 하나로 재사용할 수 있게 만드는 방법**이다.

예를 들어 숫자 리스트와 문자열 리스트가 있다고 하자.

```ts
class NumberList {
  constructor(private list: number[]) {}

  push(data: number) {
    this.list.push(data);
  }
}

class StringList {
  constructor(private list: string[]) {}

  push(data: string) {
    this.list.push(data);
  }
}
```

두 클래스는 저장하는 타입만 다르고 구조는 같다.

이런 중복을 제네릭으로 줄일 수 있다.

---

**2. 제네릭 클래스 만들기**

클래스 이름 뒤에 타입 변수를 선언한다.

```ts
class List<T> {
  constructor(private list: T[]) {}

  push(data: T) {
    this.list.push(data);
  }

  pop() {
    return this.list.pop();
  }

  print() {
    console.log(this.list);
  }
}
```

여기서 `T`는 리스트가 저장할 요소의 타입이다.

```text
T
├─ list의 요소 타입
├─ push 매개변수 타입
└─ pop 반환값의 요소 타입
```

`pop()`은 배열이 비어 있을 수도 있으므로 실제 반환 타입은 `T | undefined`로 추론된다.

---

**3. 숫자 리스트 만들기**

```ts
const numberList = new List([
  1,
  2,
  3,
]);
```

생성자에 `number[]`를 전달했기 때문에 `T`는 `number`로 추론된다.

```text
T → number
```

따라서:

```ts
numberList.push(4);
numberList.pop();
```

는 가능하다.

반면 문자열은 추가할 수 없다.

```ts
numberList.push("5");
```

---

**4. 문자열 리스트 만들기**

```ts
const stringList = new List([
  "1",
  "2",
  "3",
]);
```

이번에는 `T`가 `string`으로 추론된다.

```text
T → string
```

따라서:

```ts
stringList.push("4");
```

는 가능하지만:

```ts
stringList.push(5);
```

는 오류가 발생한다.

---

**5. 생성자를 통해 타입을 추론한다**

제네릭 클래스는 생성자에 전달한 값을 기준으로 타입 변수를 추론할 수 있다.

```ts
const numberList = new List([1, 2, 3]);
```

```text
전달값
→ number[]

T
→ number
```

따라서 다음처럼 타입을 직접 작성하지 않아도 된다.

```ts
new List<number>([1, 2, 3]);
```

타입이 명확하게 추론된다면 생략하는 것이 일반적이다.

---

**6. 타입을 직접 지정할 수도 있다**

필요하면 클래스 생성 시 타입 인수를 직접 지정할 수 있다.

```ts
const numberList = new List<number>([
  1,
  2,
  3,
]);

const stringList = new List<string>([
  "1",
  "2",
  "3",
]);
```

이 경우 `T`가 명시적으로 결정된다.

---

**7. 타입 추론이 어려운 경우에는 직접 지정할 수 있다**

예를 들어 빈 배열을 전달하면 의도한 요소 타입을 추론하기 어려울 수 있다.

```ts
const list = new List([]);
```

이런 경우에는 원하는 타입을 직접 지정하는 편이 명확하다.

```ts
const numberList = new List<number>([]);
```

이제 이후에 숫자만 추가할 수 있다.

```ts
numberList.push(1);
numberList.push(2);
```

---

**8. 제네릭 적용 전과 후**

제네릭을 사용하지 않으면:

```text
NumberList
StringList
BooleanList
...
```

타입마다 거의 동일한 클래스를 반복해서 만들어야 한다.

제네릭을 사용하면:

```text
List<number>
List<string>
List<boolean>
...
```

하나의 `List<T>` 클래스만 유지하면 된다.

---

**9. 제네릭 클래스의 핵심 장점**

```text
공통 동작
→ 한 번만 구현

달라지는 타입
→ T로 분리

사용 시점
→ 실제 타입 결정
```

즉, 타입 때문에 같은 클래스를 여러 개 만드는 문제를 해결한다.

---

**10. 전체 코드**

```ts
class List<T> {
  constructor(private list: T[]) {}

  push(data: T) {
    this.list.push(data);
  }

  pop() {
    return this.list.pop();
  }

  print() {
    console.log(this.list);
  }
}

const numberList = new List([
  1,
  2,
  3,
]);

numberList.push(4);
numberList.pop();
numberList.print();

const stringList = new List([
  "1",
  "2",
  "3",
]);

stringList.push("4");
stringList.pop();
stringList.print();

const booleanList = new List<boolean>([
  true,
  false,
]);

booleanList.push(true);
booleanList.print();

const emptyNumberList = new List<number>([]);
emptyNumberList.push(1);
```

---

**11. 핵심 정리**

* 제네릭은 클래스에도 적용할 수 있다.
* `class List<T>`처럼 클래스 이름 뒤에 타입 변수를 선언한다.
* `T`는 필드, 생성자, 메서드 매개변수와 반환값 타입에 사용할 수 있다.
* 타입만 다른 클래스를 여러 개 만드는 중복을 줄일 수 있다.
* `new List([1, 2, 3])`처럼 생성자 인수를 통해 `T`를 추론할 수 있다.
* 필요한 경우 `new List<number>()`처럼 타입을 직접 지정할 수도 있다.
* 빈 배열처럼 타입 추론이 애매한 경우에는 타입 인수를 직접 지정하는 것이 좋다.
* `pop()`은 값이 없을 수도 있으므로 반환 타입은 `T | undefined`가 될 수 있다.
* 핵심은 **`제네릭 클래스 = 동작은 하나로 재사용하고, 저장할 데이터 타입만 T로 바꾸는 구조`**이다.
