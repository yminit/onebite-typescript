# Section 7 - 3. 제네릭 인터페이스, 제네릭 타입 별칭

**1. 제네릭 인터페이스**

제네릭은 함수뿐 아니라 인터페이스에도 사용할 수 있다.

```ts
interface KeyPair<K, V> {
  key: K;
  value: V;
}
```

타입 변수의 역할:

```text
K → key의 타입
V → value의 타입
```

하나의 인터페이스를 여러 타입 조합으로 재사용할 수 있다.

---

**2. 제네릭 인터페이스 사용하기**

```ts
const keyPair1: KeyPair<string, number> = {
  key: "key",
  value: 0,
};

const keyPair2: KeyPair<boolean, string[]> = {
  key: true,
  value: ["a", "b"],
};
```

각각 다음과 같이 적용된다.

```text
KeyPair<string, number>

K → string
V → number
```

```text
KeyPair<boolean, string[]>

K → boolean
V → string[]
```

---

**3. 타입 인수는 사용하는 시점에 지정한다**

제네릭 인터페이스는 일반적으로 타입으로 사용할 때 타입 인수를 지정한다.

```ts
const pair: KeyPair<string, number> = {
  key: "id",
  value: 1,
};
```

제네릭 함수는 호출 인수를 통해 타입을 추론할 수 있다.

```ts
function identity<T>(value: T) {
  return value;
}

identity(10);
```

하지만 다음처럼 인터페이스를 타입으로 직접 사용할 때는 추론할 함수 인수가 없으므로 타입 인수를 작성해야 한다.

```ts
let pair: KeyPair<string, number>;
```

단, 제네릭에 **기본 타입**이 지정되어 있다면 생략할 수도 있다.

---

**4. 인덱스 시그니처와 제네릭**

제네릭을 인덱스 시그니처와 함께 사용할 수도 있다.

```ts
interface StringMap<V> {
  [key: string]: V;
}
```

`V`는 객체의 값 타입이다.

문자열 값을 가진 객체:

```ts
const stringMap: StringMap<string> = {
  name: "이정환",
  country: "한국",
};
```

```text
V → string
```

불리언 값을 가진 객체:

```ts
const booleanMap: StringMap<boolean> = {
  isLogin: true,
  isAdmin: false,
};
```

```text
V → boolean
```

즉, 객체 구조는 유지하면서 값 타입만 변경할 수 있다.

---

**5. 제네릭 타입 별칭**

타입 별칭에도 제네릭을 적용할 수 있다.

```ts
type StringMap2<V> = {
  [key: string]: V;
};
```

사용:

```ts
const stringMap: StringMap2<string> = {
  key: "hello",
};

const booleanMap: StringMap2<boolean> = {
  key: true,
};
```

```text
StringMap2<string>
→ 값은 string

StringMap2<boolean>
→ 값은 boolean
```

제네릭 인터페이스와 같은 방식으로 타입을 재사용할 수 있다.

---

**6. 제네릭 인터페이스 활용 사례**

학생과 개발자의 프로필이 있다고 하자.

```ts
interface Student {
  type: "student";
  school: string;
}

interface Developer {
  type: "developer";
  skill: string;
}
```

일반적인 `User`를 다음처럼 만들 수도 있다.

```ts
interface User {
  name: string;
  profile: Student | Developer;
}
```

하지만 이렇게 하면 `profile`은 항상 Union 타입이다.

```text
profile
→ Student | Developer
```

---

**7. Union 타입 방식의 문제**

학생 전용 함수에서 `school`을 사용하려면 먼저 타입을 좁혀야 한다.

```ts
function goToSchool(user: User) {
  if (user.profile.type !== "student") {
    return;
  }

  console.log(user.profile.school);
}
```

학생 전용 기능이 여러 개 생기면 같은 타입 좁히기 코드가 반복될 수 있다.

```text
Student | Developer
↓
매번 타입 확인
↓
Student로 좁히기
↓
school 사용
```

---

**8. User를 제네릭으로 만들기**

프로필 타입을 타입 변수로 분리한다.

```ts
interface User<T> {
  name: string;
  profile: T;
}
```

```text
T
→ 사용자의 profile 타입
```

학생 사용자:

```ts
const studentUser: User<Student> = {
  name: "이정환",
  profile: {
    type: "student",
    school: "한입대학교",
  },
};
```

개발자 사용자:

```ts
const developerUser: User<Developer> = {
  name: "홍길동",
  profile: {
    type: "developer",
    skill: "TypeScript",
  },
};
```

---

**9. 특정 User 타입만 받기**

학생 전용 함수라면 처음부터 `User<Student>`만 받도록 만들 수 있다.

```ts
function goToSchool(user: User<Student>) {
  console.log(`${user.profile.school}로 등교 완료`);
}
```

함수 내부에서는 이미 타입이 확정되어 있다.

```text
user
→ User<Student>

user.profile
→ Student
```

따라서 별도의 타입 좁히기가 필요 없다.

---

**10. 잘못된 사용자 전달 방지**

학생 사용자는 전달할 수 있다.

```ts
goToSchool(studentUser);
```

개발자 사용자는 전달할 수 없다.

```ts
goToSchool(developerUser);
```

함수가 요구하는 타입이 다르기 때문이다.

```text
필요한 타입
→ User<Student>

전달한 타입
→ User<Developer>
```

이처럼 제네릭을 사용하면 함수가 받을 수 있는 데이터 구조를 더 정확하게 제한할 수 있다.

---

**11. 제네릭 적용 전과 후**

제네릭 적용 전:

```ts
interface User {
  name: string;
  profile: Student | Developer;
}
```

```text
profile 타입
→ 항상 Student | Developer

학생 기능
→ 타입 좁히기 필요
```

제네릭 적용 후:

```ts
interface User<T> {
  name: string;
  profile: T;
}
```

```text
User<Student>
→ profile: Student

User<Developer>
→ profile: Developer
```

필요한 타입을 사용하는 시점에 결정할 수 있다.

---

**12. 전체 코드**

```ts
interface KeyPair<K, V> {
  key: K;
  value: V;
}

const keyPair1: KeyPair<string, number> = {
  key: "key",
  value: 0,
};

const keyPair2: KeyPair<boolean, string[]> = {
  key: true,
  value: ["1"],
};

interface StringMap<V> {
  [key: string]: V;
}

const stringMap: StringMap<string> = {
  key: "value",
};

const booleanMap: StringMap<boolean> = {
  key: true,
};

type StringMap2<V> = {
  [key: string]: V;
};

const stringMap2: StringMap2<string> = {
  key: "hello",
};

interface Student {
  type: "student";
  school: string;
}

interface Developer {
  type: "developer";
  skill: string;
}

interface User<T> {
  name: string;
  profile: T;
}

const studentUser: User<Student> = {
  name: "이정환",
  profile: {
    type: "student",
    school: "한입대학교",
  },
};

const developerUser: User<Developer> = {
  name: "홍길동",
  profile: {
    type: "developer",
    skill: "TypeScript",
  },
};

function goToSchool(user: User<Student>) {
  console.log(
    `${user.profile.school}로 등교 완료`
  );
}

goToSchool(studentUser);
```

---

**13. 핵심 정리**

* 제네릭은 인터페이스와 타입 별칭에도 사용할 수 있다.
* `interface KeyPair<K, V>`처럼 여러 타입 변수를 선언할 수 있다.
* 제네릭 인터페이스는 같은 구조를 여러 타입 조합으로 재사용할 수 있다.
* 인덱스 시그니처의 값 타입도 제네릭으로 만들 수 있다.
* 제네릭 타입 별칭 역시 `type Name<T> = ...` 형태로 작성한다.
* `User<T>`처럼 특정 프로퍼티의 타입을 사용하는 시점에 결정할 수 있다.
* `User<Student>`와 `User<Developer>`는 같은 구조를 사용하지만 `profile` 타입은 다르다.
* 특정 함수가 `User<Student>`만 받도록 제한하면 함수 내부에서 불필요한 타입 좁히기를 줄일 수 있다.
* 핵심은 **`제네릭 인터페이스·타입 별칭 = 구조는 재사용하고, 내부에서 사용할 타입만 상황에 맞게 바꾸는 방법`**이다.
