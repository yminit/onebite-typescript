# Section 7 - 5. 프로미스와 제네릭

**1. Promise는 제네릭으로 성공 결과 타입을 지정할 수 있다**

TypeScript의 `Promise`는 제네릭을 사용한다.

```ts
const promise = new Promise<number>(
  (resolve, reject) => {
    setTimeout(() => {
      resolve(20);
    }, 3000);
  }
);
```

`Promise<number>`의 `number`는 **Promise가 성공했을 때 전달할 값의 타입**이다.

```text
Promise<number>
       ↓
resolve 값 → number
       ↓
then의 결과값 → number
```

---

**2. resolve 타입이 결정된다**

`Promise<number>`로 선언하면 `resolve`에는 숫자를 전달해야 한다.

```ts
resolve(20);
```

다음은 오류가 발생한다.

```ts
resolve("20");
```

즉:

```text
Promise<T>

T
→ 성공했을 때 resolve에 전달할 값의 타입
```

---

**3. then에서도 타입이 유지된다**

```ts
promise.then((response) => {
  console.log(response);
  console.log(response.toFixed());
});
```

`response`는 `number`로 추론된다.

```text
Promise<number>
↓
resolve(number)
↓
then(response)
↓
response: number
```

따라서 별도의 타입 단언 없이 숫자 메서드를 사용할 수 있다.

---

**4. Promise 타입을 지정하는 이유**

Promise 생성 시 성공 결과의 타입을 명확하게 지정하면 이후 코드에서도 그 타입 정보가 유지된다.

```ts
const promise = new Promise<number>(
  (resolve, reject) => {
    resolve(20);
  }
);
```

핵심은 다음과 같다.

```text
비동기 작업의 결과 타입
↓
Promise<T>에 저장
↓
resolve와 then까지 타입 전달
```

---

**5. reject와 실패 처리**

`Promise<T>`의 타입 변수 `T`는 성공 결과의 타입을 나타낸다.

```ts
new Promise<number>((resolve, reject) => {
  reject("실패");
});
```

실패한 Promise는 `catch`로 처리할 수 있다.

```ts
promise.catch((error) => {
  if (typeof error === "string") {
    console.log(error);
  }
});
```

실패 값은 다양한 형태가 될 수 있으므로 사용할 때 타입을 확인하는 방식으로 처리할 수 있다.

---

**6. 객체 타입을 Promise의 결과로 사용하기**

비동기 작업에서는 객체 데이터를 반환하는 경우가 많다.

```ts
interface Post {
  id: number;
  title: string;
  content: string;
}
```

게시글을 비동기로 반환하는 함수:

```ts
function fetchPost() {
  return new Promise<Post>(
    (resolve, reject) => {
      setTimeout(() => {
        resolve({
          id: 1,
          title: "게시글 제목",
          content: "게시글 본문",
        });
      }, 3000);
    }
  );
}
```

`Promise<Post>`이므로 `resolve`에는 `Post` 타입의 값을 전달해야 한다.

---

**7. then에서 객체 타입 사용하기**

```ts
fetchPost().then((post) => {
  console.log(post.id);
  console.log(post.title);
  console.log(post.content);
});
```

`post`의 타입은 `Post`로 추론된다.

```text
Promise<Post>
↓
resolve(Post)
↓
then(post)
↓
post: Post
```

따라서 `Post`에 정의된 프로퍼티를 바로 사용할 수 있다.

---

**8. 함수 반환 타입을 Promise<T>로 작성하기**

Promise를 반환하는 함수라면 반환 타입을 직접 작성할 수도 있다.

```ts
function fetchPost(): Promise<Post> {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      resolve({
        id: 1,
        title: "게시글 제목",
        content: "게시글 본문",
      });
    }, 3000);
  });
}
```

함수 선언만 봐도 반환 형태를 알 수 있다.

```text
fetchPost(): Promise<Post>

Promise
→ 비동기 결과를 반환

Post
→ 성공했을 때 얻는 데이터 타입
```

---

**9. 반환 타입을 명시하는 장점**

```ts
function fetchPost(): Promise<Post>
```

이렇게 작성하면 함수 내부 구현을 보지 않아도 다음을 확인할 수 있다.

```text
이 함수는
→ Promise를 반환하고

성공하면
→ Post 데이터를 제공한다
```

API 호출 함수처럼 비동기 데이터를 반환하는 함수에서 특히 이해하기 쉽다.

---

**10. 전체 코드**

```ts
const promise = new Promise<number>(
  (resolve, reject) => {
    setTimeout(() => {
      resolve(20);
    }, 3000);
  }
);

promise.then((response) => {
  console.log(response);
  console.log(response.toFixed());
});

promise.catch((error) => {
  if (typeof error === "string") {
    console.log(error);
  }
});

interface Post {
  id: number;
  title: string;
  content: string;
}

function fetchPost(): Promise<Post> {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      resolve({
        id: 1,
        title: "게시글 제목",
        content: "게시글 본문",
      });
    }, 3000);
  });
}

fetchPost().then((post) => {
  console.log(post.id);
  console.log(post.title);
  console.log(post.content);
});
```

---

**11. 핵심 정리**

* `Promise`는 제네릭을 사용해 성공 결과의 타입을 표현할 수 있다.
* `Promise<number>`는 성공 시 `number` 값을 제공하는 Promise이다.
* `Promise<T>`의 `T`는 `resolve`에 전달할 성공 결과 타입과 연결된다.
* `then`의 콜백 매개변수도 같은 타입으로 이어진다.
* 객체 데이터를 반환한다면 `Promise<Post>`처럼 인터페이스를 타입 인수로 사용할 수 있다.
* Promise를 반환하는 함수는 `function fetchPost(): Promise<Post>`처럼 반환 타입을 직접 작성할 수 있다.
* 반환 타입을 명시하면 함수가 어떤 비동기 데이터를 제공하는지 선언부만 보고 알 수 있다.
* 핵심은 **`Promise<T> = 비동기 작업이 성공했을 때 얻을 값의 타입을 T로 표현하는 것`**이다.
