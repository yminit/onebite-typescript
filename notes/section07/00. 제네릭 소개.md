# Section 7 - 0. 제네릭 소개

**1. 제네릭이란?**

제네릭(Generic)은 **하나의 함수나 타입을 여러 타입에서 재사용할 수 있게 만드는 기능**이다.

적용 대상:

```text
함수
인터페이스
타입 별칭
클래스
```

특정 타입 하나에 고정하지 않고, 사용할 때 타입을 결정할 수 있다.

---

**2. any를 사용했을 때의 문제**

전달받은 값을 그대로 반환하는 함수가 있다고 하자.

```ts
function func(value: any) {
  return value;
}
```

사용:

```ts
const num = func(10);
const str = func("string");
```

문제는 반환값도 `any`가 된다는 것이다.

```text
num → any
str → any
```

그래서 잘못된 코드도 타입 검사에서 걸러지지 않을 수 있다.

```ts
num.toUpperCase();
```

실제 값은 숫자지만 `any`이기 때문에 TypeScript가 막지 못한다.

---

**3. unknown을 사용했을 때의 문제**

`unknown`을 사용하면 타입 안전성은 높아진다.

```ts
function func(value: unknown) {
  return value;
}

const num = func(10);
```

`num`은 `unknown`이므로 다음 코드는 막힌다.

```ts
num.toUpperCase();
```

하지만 정상적인 숫자 메서드도 바로 사용할 수 없다.

```ts
num.toFixed();
```

사용하려면 타입을 좁혀야 한다.

```ts
if (typeof num === "number") {
  num.toFixed();
}
```

즉,

```text
any
→ 편하지만 타입 안전성 부족

unknown
→ 안전하지만 사용할 때마다 타입 좁히기 필요
```

---

**4. 우리가 원하는 동작**

우리가 원하는 것은 전달한 값의 타입이 그대로 반환 타입이 되는 것이다.

```text
number 전달
→ number 반환

string 전달
→ string 반환

boolean 전달
→ boolean 반환
```

이때 제네릭을 사용한다.

---

**5. 제네릭 함수**

```ts
function func<T>(value: T): T {
  return value;
}
```

여기서 `T`는 **타입 변수**이다.

```text
<T>
→ 타입을 저장하는 변수

value: T
→ 매개변수 타입

: T
→ 반환값 타입
```

즉, 매개변수와 반환값이 같은 타입이라는 관계를 표현한다.

---

**6. 호출할 때 T가 결정된다**

숫자를 전달하면:

```ts
const num = func(10);
```

```text
T → number
value → number
반환값 → number
```

따라서:

```ts
num.toFixed();
```

를 바로 사용할 수 있다.

문자열을 전달하면:

```ts
const str = func("string");
```

```text
T → string
value → string
반환값 → string
```

따라서:

```ts
str.toUpperCase();
```

를 사용할 수 있다.

---

**7. 호출마다 다른 타입을 사용할 수 있다**

```ts
function func<T>(value: T): T {
  return value;
}

const num = func(10);
const str = func("string");
const bool = func(true);
```

각 호출에서 `T`는 독립적으로 결정된다.

```text
func(10)
→ T = number

func("string")
→ T = string

func(true)
→ T = boolean
```

하나의 함수를 여러 타입에서 재사용할 수 있다.

---

**8. 타입을 직접 지정할 수도 있다**

보통은 TypeScript가 `T`를 자동 추론한다.

하지만 필요한 경우 직접 지정할 수도 있다.

```ts
const arr = func<[number, number, number]>([
  1,
  2,
  3,
]);
```

여기서는 `T`를 직접 다음 타입으로 지정했다.

```ts
[number, number, number]
```

따라서 `arr`도 같은 튜플 타입이 된다.

---

**9. 배열 타입 추론**

타입을 직접 지정하지 않으면:

```ts
const arr = func([1, 2, 3]);
```

일반적으로 다음처럼 추론된다.

```ts
number[]
```

특정 튜플 타입이 필요하다면 직접 타입 인수를 지정할 수 있다.

```ts
const arr = func<[number, number, number]>([
  1,
  2,
  3,
]);
```

반대로 특별한 이유가 없다면 TypeScript의 타입 추론에 맡기는 것이 일반적이다.

---

**10. 제네릭의 핵심은 타입 관계 유지**

제네릭의 중요한 목적은 단순히 여러 타입을 받을 수 있게 하는 것이 아니다.

다음 관계를 유지할 수 있다는 점이 중요하다.

```text
입력 타입 T
↓
함수 내부에서도 T
↓
반환 타입도 T
```

`any`를 사용하면 이 관계가 사라진다.

```ts
function func(value: any): any {
  return value;
}
```

제네릭은 타입 정보를 유지한다.

```ts
function func<T>(value: T): T {
  return value;
}
```

---

**11. 전체 코드**

```ts
function func<T>(value: T): T {
  return value;
}

const num = func(10);
const str = func("string");
const bool = func(true);

num.toFixed();
str.toUpperCase();

const arr = func<[number, number, number]>([
  1,
  2,
  3,
]);
```

---

**12. 핵심 정리**

* 제네릭은 하나의 코드를 여러 타입에서 사용할 수 있게 한다.
* `any`는 타입 정보를 잃어버려 타입 안전성이 떨어진다.
* `unknown`은 안전하지만 사용할 때 타입 좁히기가 필요하다.
* 제네릭을 사용하면 입력값의 타입 정보를 반환값까지 유지할 수 있다.
* 제네릭 함수는 `function func<T>()`처럼 타입 변수를 선언한다.
* `T`는 호출할 때 실제 타입으로 결정된다.
* 숫자를 전달하면 `T`는 `number`, 문자열을 전달하면 `string`으로 추론된다.
* 필요한 경우 `func<타입>()` 형태로 타입을 직접 지정할 수도 있다.
* 배열은 보통 일반 배열 타입으로 추론되므로 특정 튜플이 필요하면 직접 지정할 수 있다.
* 핵심은 **`제네릭 = 타입을 없애지 않고, 타입을 매개변수처럼 전달해 재사용하는 기능`**이다.
